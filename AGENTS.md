# Bayan — agent instructions

- Source of truth: `docs/bayan-spec.md`. Milestones: `docs/bayan-milestones.md`; what comes next: `docs/bayan-roadmap.md`; open questions: `docs/bayan-questions.md` (answered ones: `docs/decisions/2026-11-14-004-answered-questions.md`); working rules: `docs/bayan-contributing.md`. Read the spec and the milestones before working.
- Appendix A of the spec lists settled decisions; do not re-propose them. Spec gaps go to `docs/bayan-questions.md`, with the most conservative option implemented meanwhile.
- Add an entry to `docs/bayan-progress-log.md` at the end of every working session.
- Stack: Bayān, self-hosted: the compiler is `src/` (driver, lexer, parser, semantics, emitter, sabk), built from the C seed `bootstrap/bayan.c` with a C11 compiler or zig. The C# compiler was removed in spec 019b; its last state is the tag `csharp-final` (`docs/decisions/2026-11-23-011-csharp-archive.md`). `dotnet` runs only in the weekly ddc job (`.github/workflows/ddc.yml`) and the Visual Studio extension build. No parser generators.
- Lexer works over UTF-8 bytes; tokens are structs; positions are byte offsets (`TextSpan`).
- Tests: `bash scripts/test.sh` (all parts: golden cases, Bayān `test` blocks, CLI parity, script tests, runtime C tests; `--only <part>` for one). Golden cases live in `tests/cases/<kind>/`; `BAYAN_UPDATE=1 bayan test tests/cases --only '<kind>/<class>/'` rewrites expected files. Every new diagnostic needs a `diag/` case, every runtime feature a `run/` case.
- Diagnostic codes `BYN####`: 0001–0999 lexer, 1000–1999 parser, 2000–3999 semantics, 4000–4999 backend, 5000–5999 grammar and naming, 6000–6999 effects and concurrency, 7000–7999 typestate and contracts, 8000–8999 trust and security (the ranges in use today; `docs/revisions/0017-addendum-a2-diagnostic-codes.md` assigns target areas that differ for 0xxx (project and CLI), 4xxx (control flow and failure) and 9xxx (build, C backend and runtime traps), and the codes have not been renumbered to them yet). Rendered format is fixed by the renderer tests in `src/semantics/diag.test.byn` and `src/lexer/diagnostics-t29.test.byn`.
- Scratch goes in `tmp/` (gitignored).
- Test runs: run only the selectors a change touches (`bayan test tests/cases --only '<kind>/<class>/'`). Full runs, Windows runs and mutation runs go to wp1 or wlt1 (Linux: the Debian WSL on wp1), never the working machine.
- Script output: print counts and exceptions only (failed case names, the first differing line); write full logs to `tmp/` and read them with `grep`/`tail`.
- Decisions: `docs/decisions/` (spec 010 landing gate and lessons: `2026-10-28-001-spec-010-landing-gate-and-lessons.md`; tooling ports, spec 015, replacing Python/Deno/Node scripts with Bayān or shell: `2026-11-02-002-tooling-port-rules.md` and `docs/specs/015-tooling/`); library placement: `docs/bayan-library-tiers.md`.
- Spec 010 work lands only through `scripts/selfhost/land.sh` (guard + an independent review against the C#, Q712). Tests took their expected lines from the C# implementation, never typed by hand; since 019b the C# reference is the frozen `csharp-final` tag. Port, do not invent: no fallbacks for unported siblings. The `in` parameter modifier is redundant (spec §10): leave it out of new code.
- Memory and disk bounds: read `docs/memory-leaks.md` before writing a walk, watcher, cache, child-process capture or input recursion; its *Release gate* must pass before any release.
