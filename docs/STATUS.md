# Bayān status

Version: 0.2.0 (matches `bayan --version`)
Revisions applied: 0001–0020

What was decided, where it was decided and what the compiler does, one row per feature. The feature rows are hand-kept: change a row's status in the commit that changes the feature, with its evidence. The keyword and stdlib rows are generated by `scripts/docs/gen-status.sh` from `src/Bayan.Syntax/Lexing/Keywords.cs` and `src/Bayan.Semantics/Binding/BuiltinMembers.cs`; do not edit them by hand (`scripts/docs/check.sh` fails when they are stale). Per-code diagnostic status is in [DIAGNOSTICS](DIAGNOSTICS.md). The feature rows were seeded from the 8d5e5c71 snapshot `docs/export/BAYAN-STATUS.md`.

Status values:
- `built`: parsed and checked, with a golden.
- `partial`: some forms are built and others are not.
- `spec-only`: in SPEC, not in the compiler.
- `deferred`: moved to a later round.
- `rejected`: decided against. Where the word is still lexed, it is kept only as an input form with a teaching error.
- `proposed`: only in a proposal or draft.
- `not found`: no document or code defines it.
- `unverified`: not checked.

"SPEC" is [`bayan-spec.md`](bayan-spec.md), "GRAMMAR" is [`bayan-grammar.md`](bayan-grammar.md), "rev NNNN" is [`revisions/NNNN-*.md`](revisions/README.md), "AUDIT An" is item An of [`export/BAYAN-AUDIT.md`](export/BAYAN-AUDIT.md). Golden paths (`run/`, `diag/`, `parse/`, `lex/`) are under `tests/cases/`. Source paths are shortened to file name and line.
