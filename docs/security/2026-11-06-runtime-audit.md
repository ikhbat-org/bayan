# Runtime security audit, 2026-11-06

Scope: `src/runtime/bayan-rt.c` (the C runtime every program links), read-only audit with probes (`tmp/security/`). Not reached: case tables (:690-1190), path tables (:1622-1800), `selfhost/driver/runtime.byn` (embedded copy), any run on Windows. Fix status is tracked per row in the handoff Progress log and `work/todo.md`.

| Sev | file:line | Defect | Trigger | Fix |
|---|---|---|---|---|
| HIGH | src/runtime/bayan-rt.c:1420 (`byn_arena_take`) | `n = (n + 15) & ~15` overflows when `n > INT64_MAX-15`. The result is negative, so the room check passes, `used` goes negative and a tiny block is returned for a huge write. Heap overflow. Callers only check against `INT64_MAX` (`repeated` :638, `padded` :1225). **Confirmed:** exit 138 (SIGBUS). | `using var arena = Arena()` then `provide allocator: arena { let s = "x".repeated(9223372036854775807) }`. Also `"x".padded(to: 9223372036854775807, by: ' ')` under an arena (by the same arithmetic, not run). | In `byn_arena_take`, panic when `n < 0 \|\| n > INT64_MAX - 15 - (int64_t)sizeof(byn_chunk)` before rounding. |
| HIGH | bayan-rt.c:2706-2727 (`byn_io_read_stdin`); CEmitter.cs:2276-2281; over-read at bayan-rt.c:529-538 | `Io.stdin.readAll()` returns a `string` with no UTF-8 check (tests/cases/run/io-stdin.byn says this is intended). `byn_str_next` trusts the lead byte and reads up to 3 bytes past `len`. Every rune-walking helper hits it (`case`, `padded`, `trimmed_by`, `utf16`, `runes`). Inside the 4096-byte read buffer this leaks uninitialised heap bytes into output. On an exact-size copy it reads out of bounds. **Confirmed with ASan:** `heap-buffer-overflow READ in byn_str_next bayan-rt.c:535 <- byn_str_case :1209`. | `let t = Io.stdin.readAll().value.copy(); print(t.uppercased())` with stdin `printf 'ab\xF0'`. | Validate with `byn_utf8_valid` and return `BYN_IO_INVALID_UTF8`, as `byn_io_read_text` does at :2701. Or return bytes. |
| MEDIUM | bayan-rt.c:2319-2340, 2350-2365, 2509 | Map and Symbol hashing is FNV-1a with the seed XORed into the offset basis. FNV-1a is not a keyed PRF. The seed `monotonic_nanos ^ (pid<<32\|pid)` comes from the clock and pid, not a CSPRNG. Because xor and multiply mod 2^64 only carry upward, slot `hash & mask` depends only on the low log2(icap) ≤ 31 bits of the seed. With linear probing, an attacker who learns those bits (local, or by timing) can build colliding keys and make inserts O(n²). A brute-force search for seed-independent collisions (all 2^24 3-byte strings, k=16 and 24) found none, so practical flooding is **UNVERIFIED**. | Untrusted keys from attacker-controlled input, e.g. a word-count `Map<string, i64>` or `Symbol.intern(untrusted)`, once low seed bits are known. | Replace with SipHash-1-3 keyed by 128 bits from `getentropy`/`arc4random_buf` (POSIX) or `BCryptGenRandom` (Windows), and fall back to a fixed key only in `--test`. |
| MEDIUM | bayan-rt.c:3310 (Windows only, read but not run) | `CreateProcessW(..., bInheritHandles=TRUE, ...)` passes every inheritable handle in the parent to the child, not just the two pipes and stdin. Concurrent spawns can also cross-leak pipe write ends, so a drain never sees EOF. **UNVERIFIED** at runtime. | `Io.run("tool.exe", ...)` from a program holding other inheritable handles. | Use `STARTUPINFOEXW` with `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` limited to `{stdin, writes[0], writes[1]}`. |
| LOW | bayan-rt.c:2671-2694, 2706-2727 | `Io.readFile` and stdin `readAll` read with no size cap, so a path to `/dev/zero`, a FIFO, or an endless stdin exhausts memory. Not in docs/memory-leaks.md: the "Io.run buffers child output whole" row there covers child output only. | `Io.readFile(untrustedPath)` with `/dev/zero`. | Add an optional max-bytes limit, or reject non-regular files for the whole-file read. |
| LOW | src/runtime/bayan-rt.h:271-276 (`byn_slice_range`) | `len - start` (from-end mode) and `e += 1` (inclusive) are signed overflow, which is UB. Today it wraps and the slice check catches it, but an optimiser may fold it. | `xs[^n..]` with `n = i64.min`, or `xs[0...i64.max]`. | Compute in `uint64_t`, or reject `start < 0 \|\| start > len` before subtracting. |
| LOW | bayan-rt.c:621, 645, 2303-2308 | `replaced`, `joined` and `byn_list_reserve` multiply sizes (`count*(y.len-x.len)`, `sum+sep`, `grown*elem_size`, `cap*2`) with no overflow check, unlike `repeated` and `padded`. Only reachable with inputs near 2^63 bytes, so theoretical on 64-bit. | Not practically reachable. | Use `__builtin_mul_overflow`/`__builtin_add_overflow` and panic "too long". |
| LOW | bayan-rt.c:3372-3388 | `pipe()` then `fcntl(FD_CLOEXEC)` is not atomic, so a concurrent spawn or thread can inherit the fds. If fd 1 or 2 is closed at startup, `pipe()` can return 1 or 2 and the two `adddup2` calls clobber each other. | Program started with `>&-`, then `Io.run(...)`. | Use `pipe2(O_CLOEXEC)` (Linux) or `POSIX_SPAWN_CLOEXEC_DEFAULT` (macOS), and keep the pipe fds above 2. |
| LOW | bayan-rt.c:71-77, 129-136, 304-309 | Panic, `todo` and `report_error` write untrusted text raw to stderr, while `byn_log` (:312-326) escapes control bytes, so ANSI and terminal escape injection is possible. | `panic(untrusted)` with `"\x1b]0;...\x07"`. | Route these through the same escaping as `byn_log`. |
| LOW | bayan-rt.c:2167-2181, 2098-2117 | `Path.combine(base, untrusted)` drops `base` when the second part is rooted. `byn_path_full` resolves `..` lexically. Both match .NET, but neither confines a path. | `Path.combine("/srv/data", "/etc/passwd")` or `"../../etc/passwd"`. | Document it; add a `Path.within(root, p)` check on the full path for untrusted input. |
| LOW | bayan-rt.c:354-357; CEmitter.cs:1515-1519 | The `BYN_WRITE_TRUNCATE` writer (panic and log messages, 256/512/1024-byte stack buffers) cuts at `cap` without respecting UTF-8 boundaries. A panic message built from interpolation may then be invalid UTF-8 when read back through `PanicMessage`. **UNVERIFIED**: whether the panic path trims it was not checked. | `panic($"{longMultibyteText}")` caught by a handler that reads `.message.uppercased()`. | In the TRUNCATE case, back `room` off to a code-point boundary. |

Summary:
1. Two memory-safety bugs are confirmed by running probes: arena size-rounding overflow giving a heap overflow (SIGBUS), and unvalidated stdin text giving a heap over-read under ASan.
2. Every other text source is validated: files via `readText`, argv, env, directory listings, process output, and bytes-to-string conversion.
3. The map hash should be keyed SipHash-1-3 seeded from the OS CSPRNG. No seed-independent FNV collisions were found, so flooding stays theoretical.
4. The Windows paths were read but not run. Batch quoting (`"`/`%`/CR/LF are refused, cmd.exe comes from the system directory, `.bat`/`.cmd` are refused in `Io.run`) looks sound; handle inheritance is broad.
5. Probes are in `tmp/security/{p1,p2,hash}`. No repo files were changed.

Not reached: bayan-rt.c lines 690-1190 (case tables) and 1622-1800 (path tables), the duplicate runtime in `selfhost/driver/runtime.byn` (likely has the same bugs, UNVERIFIED), and running anything on Windows.
