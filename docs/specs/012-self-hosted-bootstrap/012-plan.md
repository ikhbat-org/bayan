## Approach

The driver is a new directory, `selfhost/driver/`, compiled with the package root `selfhost/` like `bayan-emit` (`SelfhostEmitterHarness.cs:32` `Compilation.Create(sources, packageRoot: SemanticsDir)`). It ports `CliApp.Run`'s dispatch and the parts of `CliApp.cs` and `Toolchain.cs` that 009–011 left in C#, and calls what is already ported: the lexer and parser dump code (`selfhost/lexer/main.byn` `dumpFile`, `selfhost/parser/main.byn` `parseOne`), the checker's CLI layer (`selfhost/semantics/cli.byn`) and the emitter (`selfhost/emitter/main.byn`). Paths come from `std` `Path` (011 P2 and spec 014). No builtin, runtime function or emitted-C change lands before 012 passes (A1, `docs/revisions/0016-addendum-a1-midflight.md`).

Tests compare the driver with `CliApp.Run` in-process, as 009–011 do. The bootstrap test builds all three stages with one invocation, `build --package selfhost selfhost/driver`: the C# `bayan` (which gains `--package` in T5) for stage 1, the previous stage for stages 2 and 3 (spec Q2, user decision), and compares C. The golden suite then runs through stage 2.

### Decisions recorded (where the spec left room, the conservative option)

- **D1 No layout move.** Imports between `selfhost/` directories already work with the package root `selfhost/` (011's `import semantics`, `import emitter.cprint`), so the driver is one new directory and nothing under `selfhost/lexer`, `parser`, `semantics` or `emitter` moves.
- **D2 Reuse, `public` only.** Where the driver needs a lexer or parser function that is module-private (`selfhost/lexer/main.byn:33` `dumpFile`, `selfhost/parser/main.byn:37` `parseOne`, `selfhost/emitter/main.byn:37` `t12Emit`), the task makes it `public` and changes nothing else, as 011 T1 did for semantics.
- **D3 The C compiler interface** is a Bayan `interface CCompiler` in `selfhost/driver/cc.byn` with `compile` and `link` over `string` paths and a target name from `Targets.cs`; one implementation, `ZigOrCc`, holds the `FindCompiler` order. K3's sketch uses a `Path` type that does not exist and `fails BuildError`; the driver's error is a `string` as `Toolchain.Build` returns (`Toolchain.cs:170-180`).
- **D4 Scratch files** go into the output's directory under the spec Q1 default; the driver deletes them after a successful link, as `Toolchain.cs:295-296` deletes the work files.
- **D5 Runtime text** is generated by a C# test helper into `selfhost/driver/runtime.byn` as two `string` constants; the check compares the constants (read with the C# parser) with `src/runtime/`, so it needs no built binary.
- **D6 Landing** uses `land.sh` row `012` (P1). Shared state is `selfhost/driver/dctx.byn` with one `// ── Tn state` section per task (011's `lctx.byn` rule). Question ranges are five numbers per task, assigned by the dispatcher at brief time (011 D12), after whatever 014 and 015 take.
- **D7 Law tier** as 011 D11: `BAYAN_LAW_TIER` unset = stages 1–2 and a seeded golden subset; `full` = stage 3 and every case (spec Q8 default).

## Risks & mitigations

- **014 not landed.** T3 and T5 need `combine`, `directoryName` and `fullPath`. T1, T2, T4 and T8 do not, and go first. If 014 slips, the dispatcher decides whether to wait; the driver does not copy the 010 helpers (spec R4).
- **`runtime.byn` size.** About 3,700 lines of C as Bayan string constants may hit a lexer or emitter limit that no test has reached. T4's test builds the file through the harness once; a limit found there is a Question with the measured size, and splitting into several constants is the fallback.
- **Self-build time.** Each stage compiles the whole of `selfhost/` (83 `.byn` files on this branch). D7's tier keeps stage 3 out of the per-merge run; T5 measures one `safe` build of the driver; T6 records the stage times in its Questions and stops for a decision if the per-merge tier (stages 1–2, four emits) exceeds the budget T9 names (T6 design review, 2026-11-05).
- **Stage 2 differs from stage 1.** A difference means the Bayan emitter or checker differs from the C# on the driver's own sources, an L024 gap. The fix goes into `selfhost/emitter/**` or `selfhost/semantics/**` at the C# line with a C# oracle test, as 011 T13 did, under 012's row.
- **Windows.** Path behaviour depends on 014; the Q886 `/`-only failures in `selfhost/semantics/compile.byn` can also reach the driver. New Windows failures with that cause are listed in `tests/windows-known-failures.txt`; `land.sh` has no wp1 step (Q886), so the dispatcher runs wp1 before each landing.
- **Equivalence drift.** `CliApp.cs` can change under 012. Each task names its C# ranges and the review rereads them at the task's base.

### Item 1: `Target.os`, `Target.arch` (compile-time)
- **Type: `string`.** The C# works on strings (`Host` concatenation, `!= Host`, `StartsWith("windows")`), and `--target` arrives as a string. An enum would need a new enum symbol in both checkers (like `Utf8Invalid`, `Builtins.cs:100-104`) plus selfhost tables, and buys nothing for cc.byn.
- **Values:** os is `linux`, `macos` or `windows`; arch is `x64` or `arm64`, spelled as in `Targets.cs:35-40`. `wasm32` gives os `wasi`, arch `wasm32` (OQ2). A host with no Bayan target gives `""` for both, which stands in for `Host == null` (OQ3). cc.byn rebuilds the host name as `targetHost() = os == "" ? none : arch == "wasm32" ? "wasm32" : $"{os}-{arch}"`.
- **Meaning:** the constants name the target of the program being compiled, i.e. the machine the binary runs on. For the driver binary that is exactly the C# `Targets.Host`. `--target t` sets them from `t`; no `--target` (or `host`) uses the compiling compiler's host.
- **C# changes:**
  - `CompilationOptions` gets `string? Target = null`.
  - Move `DetectHost` from `Targets.cs:33-41` to a new `src/Bayan.Semantics/HostTarget.cs`; `Targets.Host` delegates to it, so the logic exists once.
  - `BuiltinKind.Target` / `BuiltinType.Target` (`Types.cs`); name binding beside `BinderExpressions.cs:551`. Member binding beside `:708` returns `new BoundLiteral(m, PrimitiveType.String, <os|arch>)`, the same node `ConstantLiteral` builds (`:610-612`). Any other member gives UnknownMember with suggestions `os`, `arch`.
  - No effect, no runtime change, no `CEmitter` case: the existing string-literal emission writes them.
  - CliApp: `Compile` passes `o.Target`, so `EmitC` follows `--target`; run, test and mutate keep `HostTarget`.
- **Selfhost:** `compile.byn` `CompilationOptions.target: string?`. A null target defaults to the selfhost binary's own `Target.os`/`Target.arch`, which is the port of `Targets.Host`, so stage 0 must have item 1 first.
