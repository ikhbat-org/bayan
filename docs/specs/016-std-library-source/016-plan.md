# 016 — Plan
Spec: ./016-spec.md

## Approach
`std` becomes a reserved first import segment. `Compilation.ResolveImport` (`src/Bayan.Semantics/Compilation.cs`)
checks `import.Path[0] == "std"` before the package-root lookup: it maps `std.a.b` to the embedded directory `std/a/b/`,
loads that directory's `.byn` files (tests excluded) as a module named `std.a.b`, and gives each file the display path
`<std>/a/b/<file>.byn` (R6). A package's own `std/` directory is never read for such an import (R2). An unknown std
module reports a new semantics code listing the shipped std modules (R3). Cycles and visibility reuse the package-module
paths unchanged (R4, R5).

Shipping (Q1 (a)): the C# embeds `lib/std/**/*.byn` as manifest resources (`<EmbeddedResource>` in
`Bayan.Semantics.csproj`, the precedent is `Bayan.Backend.C.csproj:9` for the C runtime), read through a small
`StdLibrary` table: module name → ordered (file name, bytes). The selfhost carries the same table in a generated
`selfhost/semantics/stdsource.byn` (one `const` per file plus a lookup), regenerated by a C# test under
`BAYAN_UPDATE=1`, as `SelfhostDriverRuntimeTests` does for `runtime.byn`. No file is found at run time.

Testing the mechanism before any real module ships: `CompilationOptions` gains a std-table override for tests (C#), and
the selfhost entry takes the same table, so unit tests inject `std.probe`, `std.a`/`std.b` (a cycle), and a project
with its own `std/probe/`. End-to-end `run/` cases come with the first real module (`std.json`, T4), whose cases then
join the L028 corpus. Alternative rejected: shipping a test-only `std.probe` in the binary (dead weight in every
release).

## Tech / dependencies
.NET 10 manifest resources (`Assembly.GetManifestResourceStream`, already used under NativeAOT for the runtime and
`docs/diagnostics/*.md`). No new package.

## Data / interfaces
- Display path: `<std>/<module path>/<file>.byn`.
- Diagnostic: `no std module `std.{0}`` with help listing the shipped names, sorted; empty list → "no std modules ship
  with this build".

## Risks & mitigations
- Resource names flatten directories: use `LogicalName="std/%(RecursiveDir)%(Filename)%(Extension)"` with `/`
  separators normalized at read time (Windows `RecursiveDir` uses `\`).
- Selfhost and C# tables drift: the generator test fails when `stdsource.byn` differs from `lib/std/`.
- An empty `lib/std/` until T4: the table may be empty; the code path is covered by the injected tests.
