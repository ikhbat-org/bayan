Tasks run in order; `after:` names the tasks each one needs. Plan order maps as: plan T1 → T1–T2, plan T2 → T3–T5, plan T3 → T6–T10, plan T4 → T11–T21, plan T5 → T19, plan T6 → T22, plan T7 → T23–T34, plan T8a → T35–T37, plan T8b → T38–T51, laws → T52–T67.

Rules for every task:
- `files:` names the hand-edited source files (one or two; a `-t29.test.byn` or `.test.byn` sibling counts with its source). Not counted, but named: the `src/semantics/codes.byn` entries a task reports, its explain pages and its golden case inputs. `scripts/ci/diagnostic-codes.test.sh` requires each new code, its page (`every-doc-belongs-to-a-code`, `every-doc-example-reports-its-own-code`) and its golden (`every-code-appears-in-a-golden-case`) to land together, so a page lands with the task that first reports its code, not in T1.
- `regenerates:` names generated files, never typed by hand: `docs/DIAGNOSTICS.md` (`scripts/docs/gen-diagnostics.sh`), `src/driver/diagdocs.byn` and `src/driver/runtime.byn` (`scripts/selfhost/gen-driver-files.sh --write`), `src/semantics/stdsource.byn` (`scripts/selfhost/gen-stdsource.sh`), `bootstrap/` (`scripts/ci/bootstrap-check.sh`), and every expected golden file (`BAYAN_UPDATE=1 bayan test tests/cases --only '<kind>/<class>/'`, then read against the spec).
- `src/` and `runtime/` changes land through `scripts/selfhost/land.sh`. Each task runs only the selectors it touches.
- Golden cases: `diag/<name>.{byn,diag}` and `run/<name>.{byn,stdout}` (plus `.exitcode` for traps) are flat files under `tests/cases/`; a multi-module case is a directory, as `tests/cases/diag/std-imports-package/` and `tests/cases/run/alias-field-default-import/`. All named cases are (new) unless stated.
- Paths marked (new) do not exist yet; every other path was listed and exists on this branch.
- Until ND1 and ND2 are decided, tasks follow the plan's recommended option (a) of each (see Questions).
