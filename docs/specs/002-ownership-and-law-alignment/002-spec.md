# 002 — Ownership for collections, Map API alignment, `Io.runBatch`, and proofs for laws L001–L004
Status: done (2026-10-21, 0.1.0; L005–L008 enacted 2026-10-21)
Created: 2026-10-20

## Problem

Spec 001's review found that copying a `Map` or `List` shares its heap storage: a mutation through one copy can free memory the other still uses. BYN2762 bans the `Map`/`StrBuf` cases as a stopgap; `List` is still unsafe. The user decided (handoff Q55) that collections are `unique`, with an explicit `.copy(to:)`, and that any type holding a `unique` part is `unique` (spec §3.5, §3.11).

Laws L001–L004 are enacted with statements that the code can't yet satisfy or prove:
- L001 needs both lexers to use the repository's Unicode tables and a structured `--json` dump.
- L002 needs `bayan-lex` to read stdin.
- L003 is stated over the spec's `Map` API (`map[k]`, `getOr`, `slot`, `length`), but the implementation has `get`/`set`/`count`.
- L004 needs `when` guards and `or` patterns to be handled exactly as it states.

Windows batch files are refused by `Io.run` (Q56). The user decided to add `Io.runBatch` with escape-or-fail semantics. It rejects `Untrusted<T>` arguments, so the `Untrusted<T>` type needs to exist.

## Goals

- No Bayan program that compiles can make two live values share a collection's storage through an implicit copy.
- Every enacted law has a tagged proof, and `laws-check.js --run` prints `All laws hold.`
- The `Map` API is the one spec §16 describes.
- A Bayan program on Windows can run a batch file with arguments that arrive unchanged, or get an error.

## Non-goals

- Taint sources: `main` args, stdin and file reads stay plain `string` (handoff Question). Only the `Untrusted<T>` type, `trust`, and the `runBatch` sink.
- Derived cleanup/disposal of `unique` values (§3.11's "disposed exactly once"); memory still lives in allocators.
- Borrowed struct fields, `borrows` clauses, region inference changes beyond what `move` needs.
- `HashMap`, `Set`, `Pool` (not implemented yet; they will be `unique` when they are).
- The terminal-style changes in `docs/bayan-terminal-style.md`.

## User stories

- As a Bayan user, I want the compiler to stop me from copying a list or map by accident, so that I never get two values corrupting each other's storage.
- As a Bayan developer, I want each enacted law to have a proof in the suite, so that breaking one fails the build.
- As a tool author on Windows, I want to run a `.cmd` script with arguments, so that I don't have to shell out unsafely.

## Requirements

- **R1 `unique` types.**
  - `List<T>`, `Map<K, V>` and `StrBuf` are `unique`, and so is a user `unique struct`.
  - A struct with a `unique` field, a union with a `unique` payload, and a tuple, array, optional or `Result` of a `unique` type are `unique`.
- **R2 Moves.**
  - Reading a `unique` value out of a place (local, parameter, field, element) into new storage is a compile error unless written `move x`. New storage means an initializer, an assignment, a construction argument, a collection element, a `move` parameter or a `return`.
  - `return` of a local variable moves it implicitly.
  - A moved variable can't be used on any path after the move, until it is assigned again.
  - Moving out of a field, element or `ref` parameter is a compile error.
  - Fresh values (calls, constructors) are never copies.
  - Passing to a read-only parameter, `ref`, member access, `for` iteration and formatting borrow; they don't move.
  - The error offers fixes: `move x`, `x.copy(to: alloc)` when the type has one, or `ref`.
- **R3 Explicit copies.** `List<T>.copy(to: alloc)`, `Map<K, V>.copy(to: alloc)` and `StrBuf.copy(to: alloc)` produce an independent value, so mutating either never affects the other.
  - `copy` is shallow over `unique` elements: a `List<List<T>>` copy is a compile error until elements can be copied.
- **R4 BYN2762 superseded.** The `Map`/`StrBuf` copy ban becomes the R2 rule and covers `List`. Each existing BYN2762 case either compiles (as a `move`) or gets the R2 diagnostic.
- **R5 `Map` API (spec §16).**
  - `map[k]` reads and panics when `k` is missing.
  - `map[k] = v` inserts or updates.
  - `map.getOr(k, d)` reads without inserting.
  - `ref map.slot(k)` gets or inserts the default value; it requires a defaultable `V` and is a diagnostic otherwise.
  - `remove(k)`, `clear()`, `contains(k)`, `length`, and iteration in insertion order.
  - `get`, `set` and `count` are removed; existing programs and goldens migrate.
- **R6 Shared Unicode data (L001).**
  - The C# lexer takes identifier classes and NFC data from tables generated by `tools/Bayan.UnicodeGen` from the same Unicode version as `selfhost/lexer/unicode-tables.byn`.
  - Nothing in the lexer calls `string.Normalize`, `IsNormalized` or `Rune.GetUnicodeCategory`.
- **R7 Structured lexer dump (L001).** `bayan lex --json` and `bayan-lex --json` print the same JSON document:
  - tokens with kind, span, value text and doc-comment attachment;
  - diagnostics with code, severity, span, message, label, help and fixes.
- **R8 Stdin input (L002).** `bayan-lex` with no path, or with `-`, reads its input from stdin. A failure to read the input exits 4.
- **R9 Union switch exhaustiveness (L004).**
  - BYN2410 treats an arm with a `when` guard as covering nothing.
  - An `or` pattern covers each of its alternatives.
  - Only bindings (`let`/`var`) or `_` subpatterns make a variant pattern covering.
  - BYN2410 names every uncovered variant.
- **R10 `Untrusted<T>`.**
  - `Untrusted(x)` wraps a value, and `trust(x, reason: "…")` unwraps it; the reason must be a non-empty string literal.
  - An `Untrusted<T>` doesn't convert implicitly to `T`.
- **R11 `Io.runBatch(path, args)`.**
  - On Windows it runs a `.bat`/`.cmd` file. Each argument is escaped for `cmd.exe` when that can be done exactly; otherwise the call fails with an `IoError` before starting anything.
  - On other systems it fails with an `IoError`.
  - An argument whose type is or contains `Untrusted<T>` is a compile error.
  - `Io.run` keeps refusing batch files with `permissionDenied`; the spec and docs point to `runBatch`.
- **R12 Proofs.** L001–L004 each have a test tagged `[Trait("Law", "L00N")]`. `laws-check.js --run` holds.
- **R13 Docs.** Every new diagnostic has a code, a docs page and a golden; every runtime feature has a `run/` case. Handoff Q55 and Q56 are marked answered, and new gap choices are recorded as Questions.

## Acceptance criteria

- **R1/R2.**
  - `var a = List<i64>(); var b = a;` is a compile error offering `move a`.
  - `var b = move a; print(a.length)` is a compile error naming the move.
  - `if (c) { take(move a); } print(a.length)` is a compile error.
  - `struct Ledger { List<i64> xs; }` copied from a variable is a compile error.
  - `return xs;` of a local compiles.
  - The selfhost lexer, `tools/lex-diff` and `examples/tally-lite` compile and pass after migration.
- **R3.** Given a list copied with `.copy(to: alloc)` and then mutated 100 times, the original is unchanged. Under ASan, the old use-after-free programs from the spec 001 review fail to compile or run clean.
- **R5.** `run/` goldens show `map[k]` panicking on a missing key, `getOr`, `slot` with `+=`, `remove`, `length` and insertion-order iteration. `slot` on a non-defaultable `V` is a `diag/` case.
- **R6/R7/L001.** The 10,000-input corpus compares `--json` dumps of both lexers with no disagreement. A test fails if the lexer source references `Normalize`, `IsNormalized` or `GetUnicodeCategory`.
- **R8/L002.** Inputs from the corpus fed on stdin exit 0 or 1 with spans inside the input. An unreadable path exits 4.
- **R9/L004.** A guard table covers: a guarded arm only, an `or` pattern, a refutable nested subpattern, a default arm, and a missing variant. Each gets the verdict the law states.
- **R10/R11.**
  - `Io.runBatch("x.cmd", [Untrusted("a")])` is a compile error.
  - The escaping function returns the exact `cmd.exe` command line, or a failure, for a table of arguments: `a b`, `a"b`, `%PATH%`, `^&|<>`, a trailing backslash, and CR/LF/NUL (fail). It is tested on every host.
  - On Windows a `run/` case round-trips arguments through an echo batch file.

## Law candidates

- **L005 (proposed already).** `Io.runBatch` passes every argument unchanged or runs nothing. Awaits enactment.
- **L6 (unique never aliases), for later enactment.** For every program that compiles, no two live values share the storage of a `unique` value, unless one is a borrow (`ref`, span, read-only parameter) whose region is inside the owner's.
