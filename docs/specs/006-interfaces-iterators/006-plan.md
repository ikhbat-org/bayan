## Approach

**Interfaces as a new symbol kind, conformance as a checked table on structs, dispatch by rebinding.** `InterfaceSymbol` (not a StructSymbol subclass) holds abstract methods and getters (mutating when declared `ref this`), default methods (a `FunctionSymbol` with a body whose `this` type is a synthetic `TypeParameterType("Self")` constrained to the interface) and associated types (`type Item;`, no bounds, D7). Interfaces are generic the same way structs are (TypeParameters/Template/TypeMap; a new `InterfaceSymbol` case in `Compilation.InstantiateType`, Compilation.cs:885). Only a struct lists bases after `:` (D2); a base list on a union or enum parses and is reported as not supported yet (BYN2815). A conformance pass after `DeclareMembers` and before bodies builds a `Conformance` (type, interface instance, member→witness map, associated-type map) and reports missing/mismatched members at the type. A default method is checked **once** on its template (Self is a type parameter, so it has no fields, satisfying R3 for free) and **cloned per conformer** with `Owner = conformer`, `TypeMap = {Self→conformer} ∪ interface args`, appended to the conformer's `Methods`/`Properties` and enqueued on the existing `_instantiationWork` worklist. Rationale over "emit once with a `void*` receiver": the clone is an ordinary method of the conformer, so `this`, mangling, declared `ref this` and the emitter's `self` (CEmitter.cs:789) all work unchanged, and `c.describe()` binds through `FindMethods` with no new lookup.

**`this` in a default template.** `FunctionSymbol.Owner` stays `StructSymbol?` (Symbols.cs:183): every emitted function is owned by a struct (conformers are structs, D2). The template alone has `Owner = null` and a new `FunctionSymbol.Interface`; `HasThis` (:229) and `IsGeneric` (:224) also hold when `Interface` is set, so the template is skipped by flow analysis, lowering (Lowerer.cs:21) and emission (CEmitter.cs:789 dereferences `Owner`); `BoundThis` widens its primary constructor to `TypeSymbol` and keeps a `Struct` accessor so Lowerer/CEmitter consumers are untouched; `Binder` (Binder.cs:32) derives a `ThisType` from `container ?? fn.Interface.Self` and uses it at BinderExpressions.cs:223 and :492; implicit-`this` member lookup (:410, `LookupMember` :479) consults `ThisType`, so a bare `area()` in a default body finds the interface member. The template is generic (Self occurs), so it is bound to check and never lowered or emitted.

**Mutability is declared, on every member (HANDOFF §9, round-2 C1).** Design round 2 step 3.3 parses `ref this` as parameter 0 and sets `FunctionSymbol.IsMutating` from the declaration; inference becomes the BYN2115 check. 006 reuses that parse and flag for abstract and default interface members: read-only is the default, `ref this` marks a mutating member, and there is no `readonly` member marker. Getters are read-only (round-2 J7). Since mutability is declared, the conformance pass is one phase before bodies: witnesses, associated types and the `ref this` match (a witness whose `ref this` differs from the abstract member's, in either direction, is BYN2814). A witness or default whose body mutates `this` without `ref this` is round 2's BYN2115, not a 006 code. `MutationChecks` reads `Callee.IsMutating`, so calls through a constraint in a template (callee = the abstract symbol) need a writable receiver exactly when the member takes `ref this`.

**Static dispatch is the instance rebind.** Inside a generic template, `t.area()` with `where T : IShape` binds to the interface member (a `BoundCall`/`BoundMethodGroup` whose Function is the abstract symbol). Instances are rebound from syntax with `TypeMap`, so in the instance `t` is `Circle` and `BindValueMember` (BinderExpressions.cs:638) finds `Circle.area` or the cloned default directly. No new bound node, no runtime dispatch (R6).

**Constraints are checked at definition, satisfaction at the use site.** `TypeParameterType` gains `Constraints`. The `TypeParameterType` case at BinderExpressions.cs:684 consults the constraints' members with Self→T and interface args substituted before falling back to BYN2744 (BYN2806 when the constraints exist but lack the member). `InstantiateFunction` (:859) and `InstantiateType` (:885) check each argument against the parameter's constraints inside the same `Instantiating(site, span, …)` call that declares the signature, so the first-pass bookkeeping at :869-878 applies as-is; `Instantiating` (:843-856) forwards `ConstraintNotSatisfied` to the use-site span alongside the three codes at :851, so a failing call inside another generic's body never reaches the internal-error throw at :798. Primitives never conform (D5): a primitive argument is BYN2807 with a help saying so. A generic conformer (`Wrapper<T> : IShape`) is checked once on its template; `InstantiateType` then maps each template witness to the instance's twin (same `Decl`, as `TemplateOf` :929 does) and clones the defaults with Self→instance, so instance witnesses exist before any call binds. A `TypeParameterType` argument satisfies `I` iff its `Constraints` include `I`; otherwise BYN2807 at the call in the template, and instances of that call are not re-checked.

**`dyn ref I` is a borrow type with a fat pointer.** New `DynRefType(interface, readOnly)` with `IsBorrow => true` (Types.cs:35), so BYN3001/3002/3003 and the field rule at Compilation.cs:687-697 apply unchanged (R7). `Conversions.Implicit` (Conversions.cs:11) returns `ConversionKind.ToDynRef` when the target is a `DynRefType` and the source is a `StructSymbol` whose `Conformances` include the interface, a `TypeParameterType` whose constraints include it, or a `DynRefType` of the same interface going writable→readonly (identity, as Span at :25); `Conversions` stays static because conformances live on the struct symbol. A writable `dyn ref` takes its operand through `CheckWritable`; a `dyn ref readonly I` receiver refuses `ref this` members, abstract or default, at bind time (BYN2813). The lowerer keeps the operand a place (`Lvalue`, like `ArrayToSpan` at Lowerer.cs:740) and RegionAnalysis lends the operand's root (as :198 does for spans). C layout: `struct byn_dyn_<I> { void* data; const byn_vt_<I>* vt; }`; `struct byn_vt_<I>` has one slot per method and getter, defaults included; slots mirror the `fails` convention of `Signature` (CEmitter.cs:785-791): `uint32_t (*m)(void* self, params…, ret* byn_out)`. One `static const` vtable per (conformer, interface instance), registered on the first `ToDynRef` emission for that pair (like `Helper`, never for every conformance, so `-Wall` sees no unused static), filled with per-slot thunks that cast `void*` to `T*` and call the mangled method (calling through a mismatched pointer type warns under `-Wall`, which L012 now enforces). Thunks go through `Helper` (:335); vtables are data, so they get their own list emitted after the helper prototypes and before function bodies. A call through `dyn ref` is a `BoundCall` with the abstract Function and a `DynRefType` receiver; the emitter writes `r.vt->m(r.data, …)`. No runtime change.

**`for … in` over user types reuses `BoundFor` (D1).** `BindFor` (Binder.cs:536) gains a case for a `StructSymbol` conforming to one of two synthesized built-in interfaces, attaching `BoundFor.UserIteration` (a type conforming to both uses `IIndexable`) so the six existing `BoundFor` consumers keep matching:
- `IIndexable` (`type Item; i64 count { get; } Item get(i64 index);`, `get` panicking out of range; named `get`, not `at`, because collections' `at(i)` returns `T?`, HANDOFF §11, round-2 C3): lowered to `n = count; i = 0; loop { if (!(i < n)) goto brk; x = get(i); body; cont: i++ }` in the span-loop shape at Lowerer.cs:584-604, `count` read once. The iterable is iterated in place when it is a place, else spilled; RegionAnalysis adds a root loan for the loop extent (:135), so nested loops over the same collection work and the body cannot mutate it.
- `IEnumerator` (`type Item; bool moveNext(ref this); Item current { get; }`): the enumerator owns its state. An rvalue is spilled into a hidden `LocalSymbol` of kind `Var` declared by `BindFor` (so OwnershipAnalysis and RegionAnalysis see it, not a lowering temp); a named place must be writable: `BindFor` registers a `MutationCheck` whose callee is the abstract `moveNext` (`ref this`), so a `let` enumerator fails `CheckWritable` with BYN2104 and round 2's fix-it to `var`, no new code. Lowered to `loop { if (!moveNext(&en)) goto brk; x = current(&en); body; cont: }`. The root is loaned for the loop as well, since only the loop advances it.
Loops are written `for x in e` or, typed, `for T x in e` (round-2 C2; 3.1 parses both). In both, the loop variable is a `let` copy of `Item` with `BorrowsSubject = true`; a `unique` `Item` is BYN2022 at the loop (Q90). `IEnumerable` is dropped; `NotIterable` help (:570) names both protocols.

## Risks & mitigations

- **Instance errors become internal errors** (Compilation.cs:798): BYN2807 raised while binding an outer instance lands in `_scratch` and then `_instantiationErrors`. Mitigation: forward it at :851; golden with the failing call inside another generic.
- **`-Wall -Werror` on pre-existing emission**: today's C is built with `-w` (Toolchain.cs:197), so generator programs may surface unrelated warnings (unused `cont:` labels from lowering are the likely one). Mitigation: T11 first compiles a hand-written program in the grammar under the flags; local fixes (`(void)`, dropping unused labels) land in CEmitter within T11; anything larger is a new handoff Question and the law's proof notes list the exact `-Wno-…` narrowing, which would change D4 and must be stated, not hidden.
- **Vtable struct ordering**: `byn_vt_<I>` names parameter types by value; register the interface types through `Named` on first use and emit the `byn_vt_` definition after all `_typeOrder` entries, with the `byn_dyn_` typedef forward-declaring `struct byn_vt_<I>`.
- **`current`/`get` by value** break R9's "borrow" for `unique` items. Mitigation: BYN2022 at the loop (Q90); law doc and spec §3.15 record it.
- **ScanType speculation**: `dyn` is an identifier; `for dyn ref I x in …` misparses until `ScanType` (:637) learns the prefix (it has no parentheses, so round-2 J2's paren-group rule does not apply). Parse golden in T1.
- **Two-phase type parameters**: `where T : IOrder<T>` mentions T inside its own bound; resolve bounds after names exist; guard recursion in `InstantiateType`.
- **Generic interface methods** (R8 acceptance) must be declarable although generic methods are rejected on structs today; allow on interfaces only, calling one is BYN2022 (Q95).
- **Two interfaces defaulting the same member name** on one conformer: report as BYN2802 naming both; no golden required.
- **Self-hosting golden shapes**: `string` fields are borrows (Compilation.cs:694), so the golden's `Token` is `{ i32 kind; i64 start; i64 end; }`; `TokenList` owns a `List<Token>` and conforms to `IIndexable`; `TokenStream` owns its cursor and conforms to `IEnumerator`.
- **BYN2221 help change** touches existing diag goldens; regenerate with `BAYAN_UPDATE=1` in T7 only.

## Self-hosting gaps

What spec 009's port must work around, given this subset:
- No heterogeneous child lists: no `dyn I` by value and no borrowed fields means no `List<dyn ref I>`; the tree is unions plus `Owned`, visited by `switch`.
- By-value `current`/`get` (Q90): user iterables cannot yield `unique` items (nodes holding Lists), so node lists are index loops, not `for … in`.
- No generic interface methods: no `T accept<T>(…)` visitor; visitors are `dyn ref IVisitor` with one non-generic `visit` per node kind, or `switch`.
- No interface inheritance: shared members are repeated per interface or reached through a default.
- No union/enum conformance until union members land (HANDOFF §1): a union that must conform is wrapped in a struct.
- No borrowed enumerators: an `IEnumerator` either owns its data (moved in) or a collection conforms to `IIndexable`.
- No associated-type bounds: `type Item;` only; a bound is checked at the use site through the conformer's binding.
