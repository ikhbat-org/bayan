# 001 — Plan
Spec: ./001-spec.md
Context: `docs/bayan-self-hosting.md` (phases 1–2). Milestones continue the milestones doc's numbering (M13–M23).

## Approach

Extend the existing pipeline rather than bolt on a second one: new syntax in `Parser.cs`/`Nodes.cs`, new symbols in `Types.cs`/`Symbols.cs`, binder-level monomorphization, inline C structs for unions, runtime C for `Map` and growable text, and a Bayan lexer under `selfhost/lexer/` driven by a differential xunit harness that builds it through the existing `Toolchain` cache. Monomorphization lives in the binder (not lowering) because `FlowAnalysis`, `RegionAnalysis` (`MayBorrow` is type-driven) and `ErrorFlow` all run on bound bodies and must see concrete types; lowering and `CEmitter` then see ordinary `FunctionSymbol`s/`StructSymbol`s and need only name mangling. `Map<K,V>` stays compiler-known with C runtime support (like `List`), not a Bayan-source prelude: a prelude needs implicit import plumbing, generic methods on generic structs and `Owned<T>` all stable before `Map` exists, and `Map` is on the critical path for nothing in the lexer. I would move `Map` to Bayan source later if M19 generic structs with methods land cleanly and a second container is needed; nothing in this spec forces it.

Three premise corrections. (1) The dump includes rendered diagnostics, so "the lexer" is lexer + line table + `DiagnosticRenderer` port (~1,000 lines of C# equivalent), not 746 lines. (2) L1 "for every byte sequence" cannot hold across machines today: the C# NFC check uses system ICU (handoff Q6), so the generated tables pin one Unicode version and L1 holds per pinned version; CI drift becomes a visible generator assertion failure, not a silent disagreement. (3) R8 is needed by no lexer code path; it is delivered as the smallest consistent surface (`Owned<T>`) and exercised only by its `run/` case.

## Tech / dependencies

- No new NuGet. New console project `tools/Bayan.UnicodeGen` (outside `src/`, so no AOT constraint) emits `selfhost/lexer/unicode-tables.byn` (checked in). Categories come from `Rune.GetUnicodeCategory` over all code points (the .NET runtime's own data, deterministic per runtime). Normalization data (canonical decomposition, CCC, composition pairs minus exclusions, Hangul handled algorithmically) is read from `UnicodeData.txt` + `DerivedNormalizationProps.txt`, downloaded by the generator into `tmp/` for the version named on its command line; the generator refuses to emit unless (a) General_Category from the file equals `Rune.GetUnicodeCategory` for every code point, and (b) `string.Normalize(FormC/FormD)` on this machine agrees with the table-driven algorithm for every single identifier-class code point and every composition pair. The `.byn` header records the Unicode version, .NET runtime version and command. Alternative rejected: deriving CCC by pairwise `Normalize` probing (O(marks²), clever, fragile). What would change my mind: a ban on downloads in the generator, then vendor the two UCD files under `tools/`.
- Tables are restricted to identifier-relevant classes (L*, Nl, Mn, Mc, Nd, Pc, plus ZWJ/ZWNJ): ~20k `u32`s as module-level `const` arrays emitted as C `static const` (new small feature, M16).
- Runtime additions in `bayan-rt.{h,c}`: file/stdio/exit, growable writer mode, map, seeded hash, monotonic clock. All C11, no new libs.

## Changes by area

Each milestone ends green, with docs pages + `diag/` + `run/` cases (R12 is a per-milestone obligation, not a phase).

**M13 Program entry and I/O (R1, R2, R15).** First, the milestones doc's "Self-hosting readiness" section: every row of `docs/bayan-self-hosting.md`'s table, its status (v0.1 / spec 001 milestone / next spec), and a correction that file I/O and args were not in v0.1.  `Parser.cs`: attributes `[Name(args)]` on declarations and error variants (`Nodes.cs` `Attribute`); unknown attribute names are errors. `Compilation.cs`/`Binder.cs`: `main` may be `void|i32 main()` or `… main(ReadOnlySpan<string> args)`, with or without `fails`. `CEmitter.EmitMain`: builds `byn_str[]` from argv, validates UTF-8, returns `main`'s `i32`, maps a failing variant with `[ExitCode(n)]` through a generated `byn_exit_codes[]`. `Builtins.cs`: builtin type `Io` (static-only) with `List<u8> readFile(string) fails IoError`, `string readText(string) fails IoError`, `void writeFile(string path, ReadOnlySpan<u8> bytes) fails IoError`, `Io.stdout.write(string)`, `Io.stderr.write(string)`, `i64 Io.monotonicNanos()`; builtin `error enum IoError { notFound, permissionDenied, invalidUtf8, other }` numbered first in `ErrorVariants`. Runtime: `byn_io_*` over `fopen`/`fread`, errno mapping. `run/` cases: args echo, exit 7, copy file, missing file, invalid UTF-8 as text vs bytes. `CliTests`: `bayan run prog.byn -- a "b c"` already forwards `ProgramArgs`.

**M14 Growable strings (R3).** Runtime `BYN_WRITE_GROW` mode with `byn_alloc*`. `Builtins.cs`: second constructor `StrBuf()` (`BuiltinFunction.StrBufGrow`) allocating from `context.allocator`; `.str` borrows as before, and `RegionAnalysis.AllocatedFrom` treats a growable `StrBuf` like a `List` created under `context` (Q29). `$"…"` becomes an expression of type `string` anywhere (lifts BYN2224): lowering wraps it in a temp growable writer and takes `.str`; region = context allocator. `run/`: 100,000 appends.

**M15 Processes, directories and `lex-diff` (R13, R14).** `Builtins.cs`: `List<string> Io.listDir(string path) fails IoError` (names only, sorted by byte order so output is deterministic) and `ProcessResult Io.run(string program, ReadOnlySpan<string> args) fails IoError`, where `ProcessResult { i32 exitCode; string stdout; string stderr; }` is allocated from `context.allocator`. `program` is looked up on `PATH` the way `Toolchain.FindOnPath` does. Runtime: POSIX `posix_spawnp` with two pipes drained by `poll`; Windows `CreateProcessW` with overlapped pipes. Arguments are passed as a vector, never through a shell. `IoError` gains `notADirectory`, so a missing program is `notFound`. Phase-1 tool `tools/lex-diff/main.byn`: `lex-diff --left "<cmd>" (--right "<cmd>" | --golden <ext>) <dir>`. It runs the command(s) on every `.byn` in `<dir>`, compares outputs line by line, and prints `<file>:<line>: <left> | <right>` for the first difference per file. Exit 0 if all agree, 1 if any differ, 2 on usage errors. `CliTests` build `lex-diff` and run it with `bayan lex` against the `lex/` goldens (exit 0) and against a tampered copy (exit 1, names the file). `run/` cases: spawn `bayan --version`, a missing program, a three-file directory.

**M16 Plain enums + static data (R5 subset).** `Parser.cs`: `enum Name { a, b; }`; `Symbols.cs`: `EnumSymbol`/`EnumMemberSymbol` (`TypeSymbol`, ordinal `i32`). Members `count`, `values` (`ReadOnlySpan<E>` over a static array), `name`, `ordinal`, `fromOrdinal(i64): E?`, `parse(string): E?` (linear scan; perfect hash is unobservable). `switch` exhaustiveness reuses BYN2410 with a label listing missing members. Module-level `const T[N] x = {…}` of literals → `static const` (needed by M22 tables). Equality/format helpers in `CEmitter`.

**M17 Enums with data (R5).** `enum Planet(f64 mass, f64 radius) { mercury(…), earth(…); }`: parameters become readonly members backed by `static const` per-field arrays indexed by ordinal; arguments must constant-fold (`ConstantFolding.cs`), else a new diagnostic. No methods/properties on enums yet (gap Q44).

**M18 Unions, exhaustive switch, patterns (R4).** `Parser.cs`: `union Shape { Circle(f32 r), Rect(f32 w, f32 h), None }`; construction `Shape.Circle(1)` and target-typed `.Circle(1)`; patterns `.Circle(let r)` / `.Circle(var r)` / `.Circle(_)` / `.None` in `switch` and `is` (positional only; property patterns on payloads deferred). `BoundNodes.cs`: `BoundUnionPattern(Variant, Subpatterns, Locals)`; `Lowerer.Match` adds a tag test plus payload loads (patterns remain boolean expressions). Exhaustiveness through the existing `CheckExhaustive` (BYN2410). `MayBorrow`: a union may borrow if any payload field may. `CEmitter`: tag + C `union` of per-variant structs; equality by tag then payload; format `Circle(r: 1)`, unit variant `None`.

**M19 User generics (R6).** `Types.cs`: `TypeParameterType`. `Symbols.cs`: `TypeParameters` on `FunctionSymbol`/`StructSymbol`/`UnionSymbol`; `Compilation.Instantiations : Dictionary<(Symbol, TypeSymbol[]), Symbol>`. Templates are bound once with `TypeParameterType`s for diagnostics; without constraints the only legal operations on a `T` value are copy, `==`/`!=`, pass, store, return and format, so the template catches every error. `BinderCalls.cs`: at a call, infer type arguments by unifying parameter types against argument types (explicit `f<i64>(…)` arrives through the existing `NameExpr.TypeArgs`); the instantiation is a fresh `FunctionSymbol` re-bound from the same `FunctionDecl` with a substitution map, diagnostics suppressed (any diagnostic there is an internal error and asserts). `BindAll` drains an instantiation worklist before `InferErrorSets`; `ErrorFlow` on instantiations is identical to the template's because `T` has no fallible operations, so inferred sets are copied from the template rather than recomputed. `FlowAnalysis`/`RegionAnalysis` run only on instantiations (concrete `MayBorrow`); templates are skipped. Generic structs/unions instantiate on first type reference (`TypeResolver.cs`), methods with their owner. Lowering is unchanged; `CEmitter` mangles `byn_<mod>_<name>__<Key(T)>…` using the existing `Key`. `run/`: one function at three types; the test also greps the emitted C for exactly three instantiations. `List`/`Span` stay compiler-known; a user generic may take a `List<T>` and it instantiates normally.

**M20 `Map<K,V>` (R7).** `Types.cs`: `MapType(Key, Value)`; `TypeResolver` accepts `Map`; keys limited to integers, `string`, plain enums, `char`, `bool` (new diagnostic otherwise). Members: `set(k, v)`, `get(k): V?`, `containsKey(k)`, `remove(k): bool`, `count`, `clear()`, `for (let e in m)` with `e.key`/`e.value` in first-insertion order. Runtime: compact-dict layout (dense entries array with tombstones + open-addressed `int32_t` index), generic over element sizes with per-instantiation hash/eq functions generated as `CEmitter` helpers; seeded FNV-1a 64, seed from the generated `main` (`0` under `--test N`, else time⊕pid). Rehash compacts tombstones. `set` is structural (Q30); `for` holds a loan like `List`. `run/`: 10,000 inserts with repeats, removals.

**M21 Recursive data via `Owned<T>` (R8).** Spec §9.1 names `Owned<T>` for allocator-owned heap values; the subset surface is `Owned<T>` = non-null pointer into `context.allocator`, built with `Owned(value)` (same builtin-constructor idiom as `Arena()`/`StrBuf(buf)`), read with `.value`, member access auto-derefs. A struct/union may name itself only through `Owned<…>` (direct recursion is a new diagnostic). Copying an `Owned` copies the pointer; no `unique`/`move` in this subset. Region: an `Owned` borrows the allocator it was created under, exactly as a `List` does (Q29), so storing a node past its `using` arena is BYN3002 unchanged. `MayBorrow(Owned<T>) = true`. `run/`: expression tree evaluated; `diag/`: node escaping its arena.

**M22 Unicode tables, Bayan lexer, differential harness (R9, R11).** `tools/Bayan.UnicodeGen` + `selfhost/lexer/{main,source,tokens,lexer,diagnostics,dump,unicode-tables}.byn`. Ports, 1:1 by method: `SourceText` line table; `Lexer`/`LexerState` (mode stack as a fixed `ModeEntry[16]` array, matching Q5); `Keywords`; `DiagnosticRenderer.Render/RenderAll/Display/Indent/ApplyFix` (stable sort by span start); `TokenDump`. `TokenKind` is a Bayan enum with camelCase members; the dump upper-cases the first byte of `.name` (every C# name is a capitalised camelCase word, so this is exact). NFC: on a non-ASCII identifier, decode to a `List<char>` in a per-file arena, full canonical decomposition (table + Hangul), canonical ordering by CCC, composition with blocking; if the result differs from the input, report BYN0005 with the fix text re-encoded through a growable `StrBuf`. Once the lexer exists, `lex-diff --left "<bayan-lex>" --golden .tokens tests/cases/lex` must exit 0, and the suite runs it. Harness `tests/Bayan.Tests/SelfhostLexerTests.cs`: a static `Lazy` builds `selfhost/lexer/main.byn` once per test process via `Compilation.FromPath` + `Toolchain.Build(…, Fast)` under `BAYAN_CACHE=tmp/cache` (same as `RunTests`), so the zig step is a content-hash cache hit after the first run; a `[Theory]` over `Golden.Cases("lex")` runs the binary and compares stdout to the `.tokens` golden with `Golden.Compare` (first-difference report names the line, which is the token or diagnostic). Build failure fails every case with the compiler output.

**M23 Corpus and timing (R10, R11).** Deterministic generator (xorshift, fixed seed) in the test: 10,000 inputs mixing grammar fragments from the `lex/` cases, byte mutations, invalid UTF-8, unbalanced `$"{`, non-NFC identifiers, bidi controls; written to `tmp/corpus/`, lexed in one child process via `--many <dir>` (one process per input would cost ~30 s) and compared with in-process `TokenDump.Dump(Lexer.Lex(...))`. L2 is checked on the same corpus (exit 0, no panic, spans inside input). Timing: 1 MB file built as in `LexerTests`; Bayan side `--time` prints nanoseconds around lexing only; C# side `Stopwatch` around `Lexer.Lex`; median of 5 each; assert ≤ 10×; skippable with `BAYAN_SKIP_TIMING=1` for slow CI boxes. Handoff Questions 40+ and progress log; spec sections touched: §3.5, §3.12, §3.13, §8, §9.1, §11, §13.1.

## Risks & mitigations

- **Unicode version drift** (system ICU vs tables): generator assertions fail loudly; the `nfc.byn` golden and corpus NFC cases catch runtime drift; handoff records the pinned version.
- **Monomorphization × region/error analysis**: templates never analysed, instantiations always; instantiation-time diagnostics assert. Invariant tested by a `diag/` case per illegal template operation.
- **Binding cost** (N+1 bindings per generic): acceptable at this program size; instantiations are memoised by `(symbol, args)`.
- **Test-suite cost**: one zig build of the lexer (seconds cold, cache hit after) plus 21 + 1 child processes; corpus is one process.
- **Timing flakiness**: 10× margin, median of 5, env opt-out.
- **Renderer parity** (caret width by scalars, tabs, fix line ranges): ported line by line; every existing `lex/` golden with diagnostics is a direct check.
- **Growable `$"…"` leaking under `General`**: by design in v0.1 (Q31); recorded.

## Gap decisions

40. `main` may return `i32` or take `ReadOnlySpan<string> args`; a failing `main` exits the variant's `[ExitCode(n)]`, else 1. Unknown attributes are errors.
41. Non-UTF-8 argv: the runtime reports `error: argument N is not valid UTF-8` and exits 1 before `main` runs.
42. `Io` is the blocking implementation and the only one; `context.io` indirection deferred. `IoError` is a builtin error enum with four variants; errno values outside the mapping are `other`.
43. `StrBuf()` grows from `context.allocator`; `$"…"` is an expression anywhere, allocating from `context.allocator` (never freed under `General`, Q31); its result borrows that allocator's region.
44. Enums: `i32` ordinal, declaration order; `parse` is a linear scan; associated data must constant-fold; no methods, properties or constant-specific bodies on enums yet; no `flags`/`open`/`extensible`.
45. Unions: variants PascalCase, positional payloads only, patterns `.V(let x, _)`; tag = declaration order; format `Circle(r: 1)`; equality by tag then payload; unions in `catch (e) switch` unchanged (error unions deferred).
46. Generics: no constraints at all; inference by unification only (no target-type inference); monomorphized in every build mode (spec's debug witness tables deferred); instantiation diagnostics are internal errors; no generic methods on non-generic structs beyond free functions and members of generic structs.
47. `Map`: keys are integers, `char`, `bool`, `string`, plain enums; no indexer; `set` is structural modification; iteration yields entries with `key`/`value`; seed 0 under `--test`, else time⊕pid; `HashMap` not provided.
48. `Owned<T>`: `Owned(value)` from `context.allocator`, `.value` read, auto-deref for members, copyable pointer, never null, never freed except with its arena; region rules as `List`. No `unique`/`move`.
49. L1 holds per pinned Unicode version; the C# lexer's NFC answer follows system ICU (Q6) and may differ on another machine; tables regenerate only deliberately.
50. Corpus seed and generator live in the test; timing median of 5, opt-out via `BAYAN_SKIP_TIMING`.
51. Module-level `const T[N]` of literal scalars is static data; any other `const` array is a diagnostic.
52. The Bayan dump derives C# `TokenKind` names by upper-casing the first byte of the enum member name; a C# kind whose name is not a capitalised camelCase word would need a table (none exist today; `LexerTests` should assert this).
53. `Io.listDir` returns names sorted by byte order, without `.` and `..`. `Io.run` never uses a shell, captures both streams completely (no streaming), inherits the environment and the working directory, and has no timeout yet.
54. `lex-diff` lives in `tools/lex-diff/` as a Bayan script-style program built by the bootstrap compiler. It compares outputs line by line after normalizing CRLF, the same as `Golden.Compare`.
