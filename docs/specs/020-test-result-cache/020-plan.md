## Approach
Key choice. Three candidates were weighed:

| Candidate | Sound? | Hit rate | Verdict |
|---|---|---|---|
| (a) declared inputs per unit kind, by content | while every list is complete; a missing input hides a failure until the next nightly verification sees the read | high, on every host | **chosen as the key** (owner 2026-11-28: hybrid) |
| (b) traced inputs: what the process tree really read | not complete: misses clock reads through the vDSO and metadata-only checks, and the first design digested toolchain roots by names, sizes and modification times (Neon review, 2026-11-28) | high, Linux only: wp1's Windows goldens (16,603 s) gain nothing | **kept as the nightly verifier** of (a), not the key |
| (c) coarse key: whole tree + toolchain + env | yes for in-repo files | hits only an identical tree | not added: (a) already hits whenever (c) would. The one existing instance (`wp1-test.sh`, plan 008 D) is tightened, spec Q2 |

Why the hybrid is sound enough: a deterministic unit whose declared inputs, toolchain content and environment are unchanged gives the same result, provided the declared list holds everything it consults. The list is not trusted: every night the verifier runs each unit under `strace -f` and fails on any read outside its list (R27), so an incomplete list is found within a day; R16's sampled reruns and R15's shadow comparison catch a hidden failure on the way; and R13 keeps the cache off for every gate that reaches `main` or a release. What neither the list nor the trace can see (clock, randomness, network, other processes) is handled by construction (scrubbed environment, R4) or by exclusion (R10, R11). The residual is the bounded risk the spec states.

Mechanics. Everything is repo tooling in Bayān programs in `tools/` (decision `docs/decisions/2026-11-28-012-scripts-speed-interop-hardening-wasm.md` §1), run by `$BAYAN_EXE` on every host. One tool, `result-cache.byn`, owns key, store, lookup, eviction, verification parsing and report; `scripts/test.sh` calls it per part when the switch is on.

1. **Unit** = what `scripts/test.sh` schedules today: (a) the golden cases of one class folder, selected as `$BAYAN_EXE test tests/cases --only '<kind>/<class>/'` (the runner already keeps a class in one shard, `BAYAN_TEST_SHARD`); (b) one Bayān package, `$BAYAN_EXE test --package src src/<m>` or `test lib/std/<m>`, its `test` blocks; (c) one parity tool, `scripts/parity/run.sh <tool> --impl $BAYAN_EXE`; (d) one script-test group of `scripts/ci/script-tests.sh`; (e) `runtime/tests/run.sh`. `BAYAN_EXE` is already built (`bootstrap-build.sh`), so no build step runs inside a unit. Today a part reports only a summary line and its log (`<root>/tmp/test.XXXXXX/<part>.log`); a task first makes each part write one structured result line per unit (unit, outcome, test count, seconds) to the log directory, and the cache reads only that file, never the free-text log.
2. **Key** = SHA-256 over the declared inputs by content (R2): the `BAYAN_EXE` binary, `runtime/` (`bayan-rt.c`, `bayan-rt.h`, `libc-uses.txt`, `tests/`), `lib/std/`, the unit's own files (golden: `tests/cases/<kind>/<class>/`; bayan: the `src/` package root, since `--package src` lets a module's tests import any other, or nothing more for `lib/std/<m>`; parity: `tests/parity/cli-<tool>/` and `scripts/parity/run.sh`; script group: the files its `input` rows name; runtime: nothing more), the `input` rows of `result-cache.tsv` for the unit's kind, the toolchain identity (R5), the allow-listed environment (R4) and the tool digest (R8). Paths inside the checkout are relative to the repo root. File digests are memoised per run.
3. **Toolchain identity** (R5, Neon hole 1) = `zig version` and the C compiler's version output, plus SHA-256 of the content of each one's executable and of every file under its root (zig's install directory; for a system C compiler, the root its `root` row names). Computed once per run; hashing the 199 MB zig executable alone took 1.4 s (plan 009), and T1 measures the whole cost per host. No name, size or modification time stands in for content. A part with no file (the macOS system libraries live in the dyld shared cache) is named in the `root` row's reason, covered by the OS version in the fingerprint, and backed by R13. The program cache's identity and its mtime-based script key (plan 009) are a separate, owner-decided cache: left as they are and never read as a test key (R6).
4. **Run with reuse on** (every host, R12): compute the fingerprint once; for each asked unit, `lookup`; hits are reported and not started; misses run in the part's normal run with the scrubbed environment (`Io.run` with `env:` holding only the allow-list), restricted to the missed units where the part's selector allows it (the golden runner's `only` is a list, `src/driver/golden.byn` `goldenListed`), else one call per unit; their structured results are stored when every test passed. A sample of hits is rerun (R16). Reports are merged into the existing `summary`.
5. **Verifier** (Linux only, R27) = `strace -f` around each unit, one process tree per unit, logging file, process and network system calls. `ptrace` sees statically linked children and raw system calls, which an `LD_PRELOAD` shim would miss (zig's own binaries make raw calls on Linux). `parse-trace` turns the log into observed reads, drops paths the unit created first (R3) and paths on the `volatile` list, and compares the rest with the unit's declared inputs: a read outside them, a network call or a write to a tracked file fails the night and prints the `bar` row (R11, R27). The R19 canaries prove the verifier before it runs; a unit that fails only under the trace is rerun once untraced (R26).
6. **Nightly**: one scheduled job runs the verifier over every unit, then the full suite with the cache computing but not using its answers, and calls `shadow` against its own store (R15). Its store is carried between nights by the workflow cache and serves nothing else (R21).
7. **Order of work**: T1 is a measurement and a go/no-go, not a build. Later tasks do not start if T1 fails its gate.

T1 gate (numbers reported to the user before T2): a current baseline of dev today, not the 2026-11-13 C# one: wall time of a full unrecorded pass on wp1's Debian WSL and of the golden part on wp1's Windows side (16,603 s per the Neon review; measured again), plus mb1 if free; the key's cost per host (fingerprint with toolchain content, declared-input digests); per-unit start-up cost; on wp1's Debian WSL first (bayan-test01 only when wp1 is busy and in use, owner 2026-11-28): `strace` present and permitted for the user tests run as, the R19 canaries by hand, and wall time of one recorded full pass; and a replay of the last 200 merges to `dev` against the declared lists giving, per host, the share of unit seconds that would have been reused. Stop and report if computing the key costs more than the reuse saves over those 200 merges, or if a recorded full pass cannot finish within the nightly job's limit.

Rejected: tracing as the key (the Neon holes above); a sandbox that denies undeclared reads (three per-OS implementations, where the nightly verifier gives the same check on one); recording the trace on macOS or Windows (`fs_usage` and DTrace need root, ETW file tracing needs administrator; not needed, since the key no longer depends on a trace); storing results in the repo's `tmp/` (worktrees and slice directories are new per run).

## Changes by area
- `tools/result-cache.byn` (new) — sub-commands `fingerprint`, `key`, `parse-trace`, `verify`, `lookup`, `store`, `sample`, `shadow`, `evict`, `stats`, `clean`, `bar`, `admit`. Key and lookup (R2, R5, R7, R8), outcome rule (R9), admission count (R10), barring (R11), verification compare (R3, R27), integrity (R17, R20), store layout and bounds (R21, R22), listing and emptying (R23), report lines (R24). Its `test` blocks, run with `bayan test tools/result-cache.byn`, are offline: lookup hit and every single-change miss (R7, R18), poisoning table (R20), corrupt and unknown-version entries (R17), failure/skip/timeout never stored (R9), admission and barring (R10, R11), eviction to the cap and staging sweep (R22), switch off (R25), the gate guard (R13), and "does not open `test-map.tsv`" (R14). Trace parsing is tested from recorded trace files kept under `tests/cases/result-cache/`, so it runs on macOS too.
- `tools/result-record.byn` (new) — the verifier's runner: runs one unit under `strace -f` with the scrubbed environment and hands the trace and the unit's declared inputs to `result-cache.byn verify`; refuses on a host without the canary marker (R12, R19); a unit that fails under the trace reruns once untraced and that result is reported, never stored (R26).
- `scripts/selfhost/result-cache.tsv` (new) — the human-kept lists, one kind per row with a reason column: `env` (allow-listed variables), `input` (declared inputs per unit kind), `root` (toolchain roots, with any part that has no file), `volatile` (system paths verification ignores), `never` (never-cache units), `bar` (units barred by a failed verification, as printed). A row without a reason is refused. Its digest is part of every key (R4, R8, R11, R27).
- `tools/result-canary.byn` (new, Linux only, skips with a message elsewhere) — the R19 canary table as `test` blocks with small probe programs (C or Bayān) that read, exec, probe an absent path, list a directory, follow a link, and do each through a child, a grandchild and a zig-built static child, plus a relative open after `chdir` in a child, an `openat` relative to a directory fd, and a read through a relative symlink; each must appear in the parsed observed list with its absolute path. Writes the host's "recorder proven" marker that `result-record.byn` requires (R12, R19).
- `scripts/test.sh`, `scripts/test.test.sh` — first (T2) each part writes one structured result line per unit to the log directory; then (T8), only when the switch is on: before each part, `lookup` per unit; hits are reported and not started, the sample and the misses run in the part's normal run with the scrubbed environment; the per-part summary line gains the reused/run counts and the per-unit reuse lines (R1, R4, R14, R16, R24, R25). `shard-test.sh` and its test were deleted in spec 019 T48b; nothing replaces its multi-host packing (see Risks).
- `scripts/selfhost/preflight.sh`, `scripts/selfhost/test-map.tsv` — not changed. Selection hands a unit list to the run; the cache receives that list and never reads the map (R14).
- `scripts/selfhost/pre-push-laws.sh`, `.github/workflows/laws-nightly.yml`, `.github/workflows/release.yml`, `.github/workflows/ci.yml`, `scripts/release/` — not changed in behaviour. `pre-push-laws.sh` and the release scripts export the switch as off at their top; a test fails if any of these files, or `docs/laws/*.md` `check:` lines, sets it on (R13). A unit is barred when any file in its declared inputs or seen by verification is named in a `proof:` line, or any command it runs is a `check:` line, of an enacted `docs/laws/*.md` file; the scan runs at `fingerprint` time (R11).
- Nightly job (R15, R27) — `.github/workflows/` has no self-hosted runner, so the scheduled job is GitHub-hosted Linux. ## Data / interfaces
- Switches (new names): `BAYAN_RESULT_CACHE=off|on` (default `off`; anything else is an error, never "on"), `BAYAN_RESULT_CACHE_DIR` (default `$XDG_CACHE_HOME/bayan-results` or `~/.cache/bayan-results`), `BAYAN_RESULT_CACHE_MAX_MB` (default 512; 0 is refused, unlike the program cache, so the store is always bounded).
- Structured unit results (T2): `<root>/tmp/test.XXXXXX/units.tsv`, one line per unit: `<part>\t<unit>\t<pass|fail|skip|timeout|crash>\t<tests>\t<seconds>`.
- Store layout: `<dir>/v1/CACHEDIR.TAG`, `<dir>/v1/units/<unit>/<entry id>.json`, `<dir>/v1/state.json` (admission counts, barred units with reason and date), `<dir>/v1/tmp/` (staging, swept after 24 h), `<dir>/v1/recorder-proven` (canary marker, Linux only: strace version, kernel, date). At most 8 entries per unit, least recently used first out; writes go to `tmp/` then rename.
- Entry: `{ version: 1, unit, tool: <digest of result-cache.byn + result-cache.tsv>, fingerprint: { os, osVersion, arch, cpus, toolchain: [{ name, version, root, sha256 }] }, env: { name: value }, inputs: [{ path, sha256 }], tests: [{ name, seconds }], recorded: { commit, date, host }, checksum }`. `checksum` is SHA-256 of the entry with the field empty. The entry id is SHA-256 of unit + tool + fingerprint + env + inputs.
- Paths: inside the checkout they are stored relative to the repo root, so a new worktree still hits; outside it they are absolute.
- Lookup: for each entry of the unit, newest first: checksum, `tool`, fingerprint and env equal; then every declared input re-hashed against the working tree (file digests memoised per run; tracked, unmodified files may take their digest from one `git ls-files -s` pass instead of a read, if T1 shows the mapping is exact). First entry that matches entirely is the hit. A dirty tree is allowed: inputs are compared by content, not by commit.
- Verification output: one `UNDECLARED: <unit> <path>` line per read outside the list, followed by the `bar\t<unit>\t<reason>` row to commit; exit 1.
- Report lines, in `summary` and on the terminal: `result cache: N units (T tests) reused from cache, M units run, S reused units rerun as a sample, B barred`, then one line per reused unit: `reused <unit> (<n> tests) from <commit8> <date> <host>`; with the switch off: `result cache: off`.
- Sample (R16): units ordered by SHA-256 of commit + unit name; the first max(1, ceil(5%)) of the hits.
- Exit codes of `result-cache.byn`: 0 ok, 1 soundness or verification failure (R15, R16, R27), 2 usage or unreadable store.

## Risks & mitigations
- **A declared list misses an input.** The accepted bounded risk: a reused pass can hide a failure on `dev` until the next night's verification sees the read. Mitigation: R27 nightly, R16 5% sampled reruns, R15 shadow, R13 gates. Residual: up to a day on `dev`, never on `main` or a release.
- **Reads the trace cannot see** (Neon: the clock through the vDSO; metadata-only checks such as `stat` or `access` whose answer depends on a modification time, not content). Verification passes them. Mitigation: three identical recordings before admission (R10), the never list, permanent barring on any disagreement. T1 greps the suite for clock and metadata use and lists the units it finds for the user.
- **Verification on Linux only.** A Windows- or macOS-only read (a path chosen by OS) is never seen. Mitigation: declared lists name OS-specific inputs per kind with a reason; R16 and R13 on every host. Residual stated, not closed.
- **An input kind the trace misses** (a system call not selected, `io_uring`, a read by a process started outside the tree such as a compiler server). Mitigation: the canary table (R19) covers each kind and gates verification; no server reuse.
- **Toolchain part with no file** (macOS dyld shared cache). Covered by the OS version and R13, named in its `root` row.
- **Program cache stale under the same write time** (plan 009 identity is path and write time). The result cache does not add this risk and does not lean on that key (R6); it is the program cache's, as decided.
- **Key cost on every run.** Hashing toolchain roots and `BAYAN_EXE` per run. T1 measures it per host; the gate stops the work if it eats the gain.
- **Nightly job limits.** A recorded full pass may not fit a hosted runner's time limit. T1 measures it; the job shards rather than skipping units, since a unit not verified that night is outside R27.
- **Imbalanced shards**: a golden shard (`test.sh --shard i/n`) whose units all hit finishes early while others still run. Accepted; packing after lookup is a later change.
- **No C#-era equivalent.** `shard-test.sh` (pack by class, `times`, `merge`, vm/wp1 slices) and the per-class XML test report no longer exist. Their roles are today's `scripts/test.sh` parts and `--shard`, the golden runner's per-case output, and the per-part log; T2 adds the per-unit result file the cache needs. Per-test timing (`seconds` in an entry) has no current per-unit source outside the golden runner; T2 reports whether the parts give it, else entries record unit wall time only. Multi-host slice merging has no equivalent and is out of scope.
- **Store growth or corruption.** Cap, eviction, sweep, checksum, atomic rename (R17, R22), with the bound test in the release memory gate.
- **Trust.** Each store is written and read by one user on one host; the nightly job's store is read only by its own shadow comparison (spec Q6). An entry is data, never executed.
