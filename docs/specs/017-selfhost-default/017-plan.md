## Approach

The driver stays one directory, `selfhost/driver/`, built with the package root `selfhost/` (012 D1). Each ported command becomes one new file beside `main.byn`, `commands.byn`, `build.byn` and `cc.byn`, and `main.byn`'s `refuse(command)` case for it (`main.byn:101-138`) becomes a call. The C# sources are `src/Bayan.Cli/{CliApp,Format,Doctor,Audit,Features,Dist,Scaffold,TerminalStyle,Progress,TestReport}.cs`, `src/Bayan.Backend.C/Toolchain.cs` (the cache) and `src/Bayan.Testing/*.cs` (coverage, schemata, mutation, quality report, gates). Everything the checker and emitter already port is reused through `selfhost/semantics/cli.byn` (`t26ParseBuildOptions`, `t26Compile`, `t26Report`) and `selfhost/emitter/main.byn` (`t12Emit`), with `public` added where needed and nothing else changed (012 D2).

Expected values never come from a person: every L028 row runs the C# CLI (`SelfhostDriverGoldenTests.CSharp`, `dotnet <Bayan.Cli.dll>`) and stage 2 (`BootstrapTests.Stage2Executable()`) on the same argv in the same directory, masks elapsed time as the law says, and compares stdout, stderr, exit code and, new for 017, the files the command wrote under the work directory (R3). The corpora are the existing ones: `tests/cases/{run,diag,diag-json,style,new,quality}` and the argument lists of the C# CLI tests (`CliTests.cs`, `CliEnvironmentTests.cs`, `CliSummaryTests.cs`, `FormatTests.cs`, `CacheTests.cs`, `ScaffoldTests.cs`, `StyleTests.cs`, `ProgressTests.cs`, `CoverageTests.cs`, `MutationRunnerTests.cs`, `GatesTests.cs`, `QualityReportTests.cs`). A corpus row the driver cannot pass is a listed skip with its Question, as `DiagSkips` (`SelfhostDriverGoldenTests.cs:69`) is today, and `DiagSkipsAreGapsInTheCli` (`:199`) keeps asserting that each skip is still a gap.

The order is the spec's D2 (easiest first). T1–T3 and T5 have disjoint files and run in one wave; T6 (walk) precedes T8 (format); T10 (coverage and schemata lowering in the emitter) precedes T11 (test) and T13 (mutate); T9 (cache) precedes T12 (dist) for `sha256.byn`. The release switch (T17) is last and waits for R1–R4 (spec D3).

## Risks & mitigations

- **Environment and timeout on `Io.run` (D6).** Blocks faithful `test`, `test --coverage`, `test --mutate` and `mutate`. T11 and T13 are ordered after T10 and the decision; every other task is independent of it. If the user decides a runtime change, it is its own task in the 012 shape (T16/T20 of 012: C#, runtime, selfhost mirrors, `runtime.byn` regenerated, `libc-uses.txt`).
- **File metadata (D7).** `RealPath` and LRU eviction cannot be ported faithfully without a link-target and write-time query. T6 ports the walk with `Fs.fileExists`-level checks and a Question for the symlink bound; T9 ports lookup, key, tag and `ReplaceFile` first and leaves `Evict` ordering to the decision. R7's M3/M5 rows stay in the C# gate until then and are listed in T16 as open.
- **`diagdocs.byn` size.** 5,777 lines of Markdown as string constants, beside `runtime.byn`'s ~3,700 lines of C; T1's generator test builds stage 1 with it once. A limit hit is a Question with the measured size; the fallback is one constant per file (324 constants) rather than one concatenation.
- **`features` needs node and builtin names.** `Features.ToJson` walks `file.Tree.Root.Members` for syntax node type names and the bound trees for builtins and diagnostics. The selfhost parser has its own node kinds (`selfhost/parser/nodes.byn`); the C# names (`GetType().Name`) must be reproduced by a name table, not inferred. T2's done-when is byte-equal JSON on every `CliTests.cs:205-227` row and on `selfhost/driver` itself.
- **Probes and schemata (T10) is the largest port** and touches the emitter under L024/L027. Its proof is byte-equal C with the C# for `--coverage` and `--mutate` on every `run/` input, and L027 unchanged for plain builds (probes are only lowered when asked).
- **Stage 2 build time (R6).** Every new driver file is compiled by every stage. T15 measures a `safe` build of `selfhost/driver` by stage 2 and by `CliApp.Run` on the same host, median of 3, and fails above 2x; T9's cache does not count (both runs use a cold cache).
- **Windows.** `doctor`, `new --git`, `dist` and `test --changed` run `git`, `zig` and `cc` through `Io.run`; wp1 `known-failures.py` is run before each landing, as 012 did.
- **Equivalence drift.** `CliApp.cs` and `Format.cs` change under 017 (the Unreleased BYN5103 lint landed this week). Each task names its C# ranges and the review rereads them at the task's base.

## Draft law amendment (T14 edits `docs/laws/028-driver-equivalence.md`; the user re-enacts)

Statement: For every case of the R10 corpus, the R2 usage corpus, and the 017 corpus (every command line of `tests/cases/{run,diag,diag-json,style,new,quality}` and of the C# CLI tests that T14 lists per command), stage 2's stdout, stderr, exit code and the set and bytes of the files it writes under the work directory equal `CliApp.Run`'s, with elapsed time masked as before (`[0-9]+\.[0-9]{2}s` → `<t>s`; `"durationMs": <number>` → `0`), the version line's parenthesised part masked (012 Q3), and cache paths under `BAYAN_CACHE` masked to `<cache>`; the comparison runs with stderr not a terminal and `CI` set, and with `BAYAN_CACHE` pointing at a fresh directory per case.

Counterexample: a corpus case (its argv, cwd and input files) and the first differing stream or file between stage 2 and `CliApp.Run`, both shown masked.

Proof notes: `BAYAN_LAW_TIER` unset = a seeded subset per command (at least one row per command); `full` = every row. The `check:` line stays `dotnet test -v q --filter "Law=L028"`; `timeout:` is remeasured by T14 and recorded in its Questions.
