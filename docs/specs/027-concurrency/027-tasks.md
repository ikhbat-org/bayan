# 027 — Tasks

Status: draft
Release: unscheduled (phase 1 planned for 0.5.0)
Sources: `./027-spec.md`

Plan: ./027-plan.md

Phase 1 is built here (plan T1–T19); T142 and T143 plan phases 2 and 3. Tasks run in order; `after:` names the
tasks each one needs, `lands with:` the task it merges with. `files:` lists every file a task touches, at most two;
a golden case `tests/cases/<kind>/<name>.{byn,<expected>}` is one entry (its input and expected files). Expected
files are written with `BAYAN_UPDATE=1 bayan test tests/cases --only '<kind>/<name>'` and read against the spec,
never typed by hand. A code or runtime task names, in `done when`, the cases a later task adds to prove it. Generated
files (`src/driver/runtime.byn` and `src/driver/diagdocs.byn` from `scripts/selfhost/gen-driver-files.sh`,
`docs/DIAGNOSTICS.md` from `scripts/docs/gen-diagnostics.sh`, `bootstrap/` from `scripts/selfhost/land.sh`,
`docs/specs/README.md` from `scripts/docs/gen-spec-index.sh --write`) are regenerated by the task that changes their
source and are not counted. `src/` changes land through `scripts/selfhost/land.sh`. An explain page lands with the
code that makes its code live (`scripts/ci/diagnostic-codes.test.sh` needs page and case). Timing cases scale with
`BAYAN_TEST_TIME_SCALE`. Full, Windows and benchmark runs go to wp1 or wlt1. "(new)" marks a path the plan creates;
"(new, named here)" marks a path the plan asks for without naming it (Questions 3).
