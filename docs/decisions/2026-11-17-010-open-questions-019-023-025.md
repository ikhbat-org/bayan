Status: decided (the owner accepted Fable's recommendation on every question on 2026-11-17: "take all defaults")
Release: unscheduled

Sources: three independent Fable reviews (think workers, keys `fable-oq-019`, `fable-oq-023`, `fable-oq-025`), one per spec. Decision 009 already settled spec 019's language server placement (C), OQ8 (C) and OQ6 (A), and revision 0024 closed spec 023 OQ1 in the spec text.

The answers are written into the open-questions section of each spec (`docs/specs/019-dotnet-exit/019-spec.md`, `docs/specs/023-spec-catch-up/023-spec.md`, `docs/specs/025-llm-eval-set/025-spec.md`). Where an answer changed a requirement, the spec says which one.

## Spec 019

| Q | Answer | Why |
|---|---|---|
| OQ2 Freeze conditions | Freeze at `v0.3.2` as it is; Q1272 and Q1186 land after 019a, self-hosted compiler only, hand-reviewed goldens. | The Q1272 rewording is in neither compiler at the tag, and waiting for it only adds a round trip; decision 006 §2 already accepts freezing and reviewing by hand. |
| OQ3 `src/` and the frozen compiler | No limit on `src/`; new check R36: the previous commit's bootstrap must build the new `src/` and emit the new `bootstrap/bayan.c`. | A limit keeps double builds for the compiler's own code for good; the chain check turns "each bootstrap comes from the one before" into something a script verifies. |
| OQ4 Classes that test C# internals | Port, or drop with a covering case, or "no counterpart" approved per row; never "proven only by the frozen compiler". | The coverage ratchet cannot see C# tests, so a frozen row is a silent drop. |
| OQ5 Other .NET projects | Remove `Bayan.SyntaxFuzz` and `Bayan.UnicodeGen` in the 019b commit; run UnicodeGen from `csharp-final`; file a port for the next Unicode bump. | Both compile files under `csharp/`, so neither builds after the removal. |
| OQ7 `bayan-lsp` in archives | Ship in all six archives from the first release after the Bayān server passes R21 and R22 (R37); never the C# build. | Each release job already has a fresh `bayan`, so it is one more file, and without it a downloader gets no server. |
| OQ9 Law numbers | L040 to L045, reservations recorded in `docs/laws/README.md`. | Laws are numbered in the order written and 032 to 037 are held for spec 020. |
| OQ10 Estimate | Keep 4 to 7 weeks until T11, then report three figures: 019a without the server, the server port, 019b. | The unknowns are the test count and owner turns, and the language server no longer sits on 019a's path. |

## Spec 023

| Q | Answer | Why |
|---|---|---|
| OQ1 `dec` | Closed by revision 0024 and §3.1: 96-bit unsigned coefficient plus sign, scale 0..=28, ties to even, traps. | The OQ text predates the revision. |
| OQ2 `checked` | Syntactic scope; calls keep their behaviour; division by zero traps; warn when nothing is covered (R8). | A callee's trap cannot become `null` without dual compilation or unwinding. |
| OQ3 `Secret<T>` | Heap-owned payload wiped on dispose; sinks added per module (R9). | A wipe is only sound if the secret owns its bytes, and a move must not leave a stale copy. |
| OQ4 `xs except p` | Lazy filter value that borrows `xs`; the standalone form waits for #15a. | It matches `where` and avoids a hidden allocation. |
| OQ5 `embed` | One per struct; every name collision is a compile error in 0.4 (R10). | An error can be relaxed later; shadowing cannot be tightened. |
| OQ6 Units | Base and scaled units only; compound declarations give BYN2022. | `std.time` is the only 0.4 user and the compound rules are unwritten. |
| OQ7 Patterns | `@positional` for deconstruction; `T(var x)` calls `tryParse` or `tryFrom`; no distinct-type unwrap. | One spelling should have one meaning. |
| OQ8 `yield` | Stays unbuilt until a revision defines return type and borrow rule. | It shares the unsettled borrow rule of §13. |
| OQ9 `provide` handlers | `clock`, `random`, `console`, `log`, `Io.Simulated`, plus built-in `fs.restricted`; fake clock is `FakeClock`. | Decision 007 Q3 already accepted `fs.restricted`; the normative spec says `FakeClock`. |
| OQ10 C types | Fixed set without `c_size` and `c_ssize`; `c_void` only behind a pointer; `CImport` deferred. | `usize` and `isize` already exist. |
| OQ11 `fuzz` and `model test` | `fuzz` runs targets in a child process (R11); `model test` stays in Phase 6. | A trap ends the process, so an in-process runner dies with its input. |
| OQ12 `xOp` | Deferred; the `model test` revision decides define or delete. | Nothing consumes it yet. |
| OQ13 Comptime API | Built-in derives generate Bayān source, not direct C (R12); §12 revision before Phase 6. | `bayan expand` then prints what was compiled. |
| OQ14 Lockfile | Path dependencies and lock v1 with SHA-256 tree hashes; no registry field. | Moving a registry later would break every lockfile. |
| OQ15 Concurrency | Phase 6, promote the design doc into §13; `Io.Blocking` first, then one worker, then per-core (R13). | A parallel pool breaks the per-worker no-race promise. |
| OQ16 `sql"…"` | Placeholder count and taint first; columns wait for a snapshot format. | Only the first two need no new file format. |
| OQ17 Process API | Handle with a combined read of stdout or stderr (R14). | Reading one pipe to the end deadlocks a single-threaded reader. |
| OQ18 Check removal | Emit every check through 0.4; measure before building range analysis. | A wrong removal pass deletes a safety check. |
| OQ19 `Symbol` | `const Symbol[N]` in Phase 3; one process-lifetime table through 0.4. | No pressure to change the table found. |

## Spec 025

| Q | Answer | Why |
|---|---|---|
| Q1 Where the set lives | `evals/llm/tasks/` at the root; the runner is not inside `evals/`. | Already in place, and a separate root makes R23 visible in the tree. |
| Q2 Ships in the repository | `dev` here; `heldout` in a separate private repository, never committed here. | This repository is public (since 2026-11-01), so a committed `heldout` task is public in every clone. |
| Q3 License | ISL-P 1.2, plus one line in `NOTICE.md` naming `evals/`. | The license already covers associated files; the gap is only that nothing names them. |
| Q4 First baseline | Strongest hosted model the owner already pays for, twice (no context, then `docs/bayan-grammar.md`); then a local base model the owner picks, same two contexts. | With 12 tasks the first run tests the set, not the model. |
| Q5 `dev` as training data | No; prompts and few-shot examples only. | `dev` is the only daily number and stops meaning anything once trained on. |
| Q6 Size and share | 240 tasks (30 per category, tiers 12/12/6), two thirds `heldout`; first cut 120. | 160 `heldout` tasks give about plus or minus 8 points, enough to see a real fine-tuning change. |
| Q7 Limits and isolation | Build 120 s, run 10 s, output 1 MiB, `limit` outcome; OS sandbox with no network, no read of the task set, writes only in scratch, macOS first. | A candidate can otherwise read the expected output, which matters once the score is a training reward. |
| Q8 CI re-check | `dev` on every push in the Linux job; `heldout` locally with a runner guard. | The point of the re-check is to catch a language change at the commit that causes it. |
