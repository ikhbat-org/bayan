## Per-task loop

One task = one branch off the base, one writer brief, one guard pass, one independent review, one `land.sh`.

```
git switch -c feat/010-t18 feat/010-self-hosted-semantics
python3 -I scripts/selfhost/wave-brief.py . T18      # writes tmp/010-t18/prompt.md
# give a writer agent tmp/010-t18/prompt.md as its whole task; it must end on GUARD PASS (the exact line is in the brief)
git add -A && git commit -m "feat(010): T18 <title>"  # the dispatcher commits the writer's work
bash scripts/bayan-tool.sh review-brief . T18    # writes tmp/010-t18/review.md
# give a DIFFERENT agent (fresh context, never the writer's summary) tmp/010-t18/review.md; it writes reviews/T18.md
# FAIL → hand the review file to the writer, fix, commit, review again. PASS → commit the review file.
git switch feat/010-self-hosted-semantics && bash scripts/selfhost/land.sh T18 feat/010-t18   # guard + review gate, --no-ff merge, tick
```

- The brief is self-contained: task text, the C# line ranges to port, the task's `010-api.md` signatures, how to test with `SelfhostSemanticsHarness`, the writer protocol (`scripts/selfhost/writer-protocol.md`), the Bayan cheat sheet (`scripts/selfhost/bayan-cheatsheet.md`) and the guard line.
- The guard checks scope, junk files, 0 build warnings, the task's tests green with none skipped, no tuple destructuring / `.N` fields, mutation testing, and (`guard-checks.py`): tests built from the C# oracle, no stub markers or empty bodies left, ctx.byn only in the task's section, no Open gating Question, a Progress log entry, Question line citations that hold.
- The guard cannot see invented logic or sibling stand-ins; the review can. Never skip it, never let the writer review itself, never land on FAIL.
- Writers never tick tasks; `land.sh` does. Two tasks merged in parallel conflict only in the handoff's *Questions* list and ctx.byn sections: keep both sides.
- Break-tests: restore the file by copying back a copy taken first. `git checkout --` restores the stub and erases the port.
- At most 2 writers at once on a shared machine, each under `nice -n 19`.
