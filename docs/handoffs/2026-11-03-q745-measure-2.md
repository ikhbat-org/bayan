## 5. finish(): spec/implementation mismatch (for a handoff Question)
- Spec, docs/bayan-spec.md:303: `finish()` "consumes the buffer and returns it as a string without copying".
- Checker, src/Bayan.Semantics/Binding/BuiltinMembers.cs:123-124: "finish() returns the text borrowed from the buffer, like view; it does not consume the buffer yet". finish() binds to BuiltinMember.StrBufAsString, as `view` does.
- Emitter, src/Bayan.Backend.C/CEmitter.cs:2242-2243: finish() and view emit the same string view of the writer.
- Runtime, src/runtime/bayan-rt.h:432: `byn_strbuf_str(byn_writer w) { return (byn_str){w.buf, w.len}; }` is a view into the buffer's storage, and the buffer stays usable afterwards.
- Growth, src/runtime/bayan-rt.c:362 (evidence from R2 amended): BYN_WRITE_GROW allocates a fresh block and never frees or overwrites the old one, so append never invalidates text already taken.
- What this branch implements, the loan-only reading: the finish() result borrows the buffer's storage plus a loan on the StrBuf local, but not the local's scope.
- `view` shares StrBufAsString but is unchanged. The new path applies only to the call syntax (`finish()`) on a local receiver.
