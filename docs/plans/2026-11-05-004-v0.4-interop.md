Date: 2026-11-05.

- **Gate:** toolchain phase 2 is done: `cc bootstrap/bayan.c` builds, and clang, gcc and TinyCC drivers exist.
- **Interop policy** (round-4 draft §3, confirmed 2026-11-05): interop is C only. C# source arrives through `bayan migrate cs`. .NET code is reached only through C ABI exports of NativeAOT libraries. There is no CLR hosting.

## Item 3: .NET pilot through JauntyQ

### Approach

JauntyQ gains a second output. From the same `.sql` files and schema snapshot, it generates:

1. **A C# export shim.** A NativeAOT class library (`<PublishAot>true</PublishAot>`, `<NativeLib>Shared</NativeLib>`). It contains one `[UnmanagedCallersOnly]` export per query, wrapping the JauntyQ-generated query code.
2. **Matching Bayān bindings.** An `extern c` block plus typed wrappers.

### Shim rules

- No exception crosses the boundary. Every export catches and returns a status code. The Bayān wrapper maps codes to a generated `union error`.
- Buffers are caller-owned (pointer plus length), so nothing is freed across runtimes.
- Calls are batch-sized: rows per call, not columns per call.
- Async queries run synchronously inside the shim. The Bayān externs are `@blocking`, so they run on the compute-offload pool.
- The shim is built per target OS (NativeAOT does not cross-compile across operating systems). `bayan build` uses a prebuilt shim for the target and fails clearly when it is missing.
- Each NativeAOT library carries its own runtime and GC. One shim per program is the recommended shape.

### Generated Bayān shape (illustrative)

```cs
@link("JauntyShim")
extern c {
    c_int jq_open(readonly u8* connection, c_int length, out i64 handle)
    c_int jq_product_name(i64 handle, i64 id, u8* buffer, c_int capacity, out c_int written)
    void jq_close(i64 handle)
}

public struct unique Catalog {
    i64 handle

    @blocking
    public string productName(i64 id) uses net, alloc fails CatalogError {
        …   // generated: unsafe call because "C ABI into the NativeAOT Jaunty shim", status → CatalogError
    }
}
```

### Acceptance

The SQLite path (the one JauntyQ's CI verifies today) works end to end. Other providers depend on their NativeAOT support and are not part of this item.

### Long term

A native Bayān port of JauntyQ's model (parking lot). It doubles as the test of whether Bayān collapses Jaunty's overload and async explosion.

## Notes for the agent

- `@export` and the `FibersOnWasm` diagnostic are new. Both must pass R4.4's keyword-budget rule, which attributes satisfy without a new keyword. Codes come from the renumbered ranges.
