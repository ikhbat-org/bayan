## Ground rules kept from the handoff (§0)

- **Additive and opt-in.** With no new flag, subcommand or variable in use, `bayan build`, `run`, `test` and `new` give byte-identical output, emitted C and binaries compared with `dev`. Checked before every merge.
- **No syntax**, and no spec or diagnostic edits. User-visible changes get a draft revision (`Status: draft`), not applied.
- **Own directories:** `docs/tooling.md`, `scripts/tooling/`, `tests/tooling/`, `bench/soa/`, and the MCP server under `tools/mcp/` (self-hosted, below).
- **Two touch points in in-flight code at most:** the `mcp`/`--watch` dispatch in `src/driver/`, and the debug allocation hook in the runtime C. Each is one commit, lands between waves, and never edits a file a current wave is changing.
- **Report-only CI;** the existing CI must not get slower. A step that fails or conflicts stops and is recorded in `docs/tooling.md`.
- **Shell or Bayān only.**

## Phases, as amended

- **T0 inventory → `docs/tooling.md`.** Write the status table and the facts from the inventory audit; time one `run/` golden. No C# questions.
- **T1 agent guide.** Add to the existing `AGENTS.md` only what is missing: `bayan format`/`bayan fix`, the JSON flags, what a `(not in 0.x)` or spec-only tag means, `docs/export/` is generated. Stays one source of truth; no compiler change.
- **T2 `bayan run --watch`** (after 027). `watch` bool in `T5Options`/`t5ParseBuildOptions`, usage error (exit 2) unless the mode is debug, dispatch from `runProgram` (`build.byn:557`) to a new `src/driver/watch.byn`. Poll `Fs.modified` every 200 ms, debounce 100 ms, rebuild through `t5Compile`/`t5EmitC`/`t5PrepareOut`, stop the child with SIGTERM then SIGKILL after 2 s, stay stopped on a compile error, Ctrl-C exits 0. Help marks it experimental. Tests in `tests/tooling/watch/` (edit; broken then fixed). Rebuild cost limits it to small packages until incremental build exists; recorded, not worked around.
- **T3 allocation report** (after 027 and the `#line` decision). `#ifdef BYN_DEBUG` branch in `byn_general_resize`/`byn_release` (`bayan-rt.c:1409-1422`), one cached `getenv("BAYAN_ALLOC_REPORT")`, flushed at `atexit`. A debug-only `ptr → {site, size}` table, since `byn_release` takes no size. Call sites by `backtrace()` skipping runtime and helper frames. All three runtime copies synced. `scripts/tooling/alloc-report.sh` resolves with `llvm-symbolizer`/`addr2line` (`atos` on macOS). Tests in `tests/tooling/alloc/`; `safe` and `fast` output byte-identical.
- **T4 MCP server.** A separate self-hosted program, `tools/mcp/`, built like `bayan-lsp`, reusing the LSP `json.byn` and `transport.byn` patterns. `src/driver/` stays untouched; a `case "mcp":` shim that execs it comes later, after audit-040 clears `src/driver/`.
  - Protocol revision: **not pinned yet.** Read it from the official MCP specification before writing the `initialize` handler, negotiate `protocolVersion`, record it in `docs/tooling.md`.
  - Framing: buffered line reader on `Io.stdin.read(to:)` (64 KiB, the `transport.byn:14-106` pattern), strip one `\r`, skip blank lines, cap the line length (over it: drain to `\n`, reply -32700). Compact one-line JSON plus `\n` on stdout; logs on stderr only. If 027's `Io.stdin.readLine(max:)` lands first, use it.
  - Bounds (`docs/memory-leaks.md`): each request in an arena; children through `Io.run` with `timeout:` (bounded capture); an RSS bound test over a long session.
  - Paths: reject empty and NUL; `Fs.realPath` on the root and the target; inside means `real == root` or `real` starts with `root + sep` (roots ending in `sep` handled), case-insensitive on Windows; `notFound` is a tool error.
  - Child: `BAYAN_EXE` if set, else `bayan` on `PATH`. Outputs returned unchanged.
  - Tools as in the handoff; writing tools only with `--allow-write`. Transcript tests in `tests/tooling/mcp/`, absolute paths normalised.
- **T5 SoA benchmark.** As in the handoff (it is parking-lot P06). `fast` mode, clang and gcc, 10 runs, median and peak RSS. The 10 × 50M sweep runs on wp1 or CI, not the working machine.
- **T6 compiler memory.** `scripts/tooling/compiler-rss.sh` over `scripts/release/peak-rss.sh`: cold self-host build per bootstrap stage and `bayan check` of `src/`. No per-phase RSS (no `--timings`). Weekly report-only job; joins plan 020's H10 job if that exists first, does not wait for it.

## Risks

- T3 call sites: helper frames and `#line "main.c"` hide `.byn` lines; frame walking plus the `#line` decision, or the report names helpers.
- T2 before 027 would put throwaway spawn, kill and sleep code into the runtime; the order forbids it.
- Runtime triple-touch (T3) conflicts with 0.4.2 and 027; lands only in a gap between them.
- Watch usefulness is bounded by 30 s rebuilds.
- Revision numbers may move if another spec claims one first.
- T5/T6 sweeps are offload work (wp1, wlt1, CI).
