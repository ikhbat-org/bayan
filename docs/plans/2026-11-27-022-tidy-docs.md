## Phase 0: write the rules down, then enforce them (inline, ~1 h)
- `docs/bayan-contributing.md` gets a short "Writing docs" section; `site/CONTENTS.md` links it. Rules:
  1. A pattern over a list: `bayan-<version>-<os>-<arch>.tar.gz` (`.zip` on Windows), not six names.
  2. Say each thing once, in the place a reader looks for it; elsewhere link.
  3. The current version only. History lives in `CHANGELOG.md`.
  4. Bayān on its own terms: no comparisons to C# or other languages to explain a rule.
  5. An example before a paragraph; a table for anything with two or more dimensions.
  6. No filler: the word list lives in `scripts/docs/prose-words.txt` (new; seeded from the owner's style rules).
- `scripts/docs/prose-check.sh` (+ `.test.sh`), run from `scripts/docs/check.sh` so CI enforces it. Over user docs only (README, `site/content/`, `bootstrap/README.md`, `editors/README.md`, the `Version:` release docs), it fails on:
  - three or more release archive names on one line or in one list;
  - `C#`, `.NET`, `dotnet`, `csharp/` in prose (Bayān's `.net` capability allowed by exact token);
  - a Bayān version string other than `VERSION` outside `CHANGELOG.md` and user-package examples;
  - the banned filler words.
  Test: one fixture per rule, each break-tested.
  Lands **warn-only**; becomes blocking after Phases 1–2 (today the spec, milestones, self-hosting doc and generated DIAGNOSTICS.md would fail it). Exempt by design: `from-go|python|rust|typescript.page` (comparison pages), `whats-new.page` (version rule), maintainer docs that describe the frozen C# oracle (`bayan-self-hosting.md`, RELEASING ddc section, `bootstrap/README.md` ddc section).

## Phase 1: brevity pass (5 writers, file ownership disjoint)
Every writer gets the same rules plus:
- Keep every fact: rule, number, flag, diagnostic code, path, command. Code blocks byte-unchanged unless the block itself is the noise.
- Generated text changes only through its generator: `docs/DIAGNOSTICS.md` (`gen-diagnostics.sh`), the generated blocks of `docs/STATUS.md` (`gen-status.sh`; its hand-kept feature rows are editable), the diag explain text.
- Spec section headings and numbers, and the `(not in …)` tags, stay byte-unchanged (`check.sh` (e)/(i) and §-citations depend on them).
- `bash site/check-examples.sh`, `bash site/build.sh`, `site/gen/test.sh`, `scripts/docs/check.sh` and the new prose check pass.
- Report prose words before/after per file. Target: 25% fewer, no fact lost.
