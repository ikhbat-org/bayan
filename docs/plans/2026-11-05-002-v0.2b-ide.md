# v0.2b: IDE and syntax API

Status: open (not started; gated on v0.2a #2).

Date: 2026-11-05.

- **Gate:** the round-4 batch is merged, and v0.2a #2 (module cache) is merged. After that, runs in parallel with v0.2a.
- **Goal:** Bayān uses mature IDEs' features (IntelliSense, tooltips, native debuggers) instead of getting in their way.

## Items

| # | Lesson | Change | Done when |
|---|---|---|---|
| 1 | B11 | Public, versioned syntax and semantic API in `std`: tree, symbols, types, diagnostics, inferred clauses. It is a read-only view over the compiler's own data, not a copy, and is versioned per edition | `bayan format` and `bayan audit` use it instead of internal types |
| 2 | B10 | Language server on that API: diagnostics with fix-its, hover (doc comments, inferred `fails`/`uses`), go to definition, find references, rename, completion, `bayan explain` text on diagnostics | Works in VS Code, and in Visual Studio through #3 |
| 3 | B10 | Thin Visual Studio extension (decided 2026-11-05): hosts the language server, adds `.byn` project recognition, build and run commands, and debug launch. No second analyzer. Native Visual Studio features are added only for specific gaps found in use | Open, edit, build, run and debug a Sūq module in Visual Studio |
| 4 | B10 | Debug adapter over the native debugger (lldb, gdb, Visual Studio). Uses `#line` mapping. Shows Bayān names for locals, `T?` values, union cases with payloads, and typestate | Step, break and inspect on a golden in VS Code and Visual Studio |
| 5 | X03 | Derivations and generators run through the same semantic model. Code in `gen/` is navigable; hover on generated code names the derivation that produced it | Go to definition lands in `gen/`; hover shows the source derivation |

## Out of scope
