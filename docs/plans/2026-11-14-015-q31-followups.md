# Plan: the Q31 follow-ups after plan 014 (frontend freed before zig, emitter and effects arenas, review LOWs)

## Context
Plan 014 (merged fce07891, pushed) brought bayan's own peak for the self-hosted `build` of the driver to 699 MB on macOS and 798 MB on Linux. The `zig cc -O2` child then runs alongside it at 1,663 MB, about 2.4 GB in total. That is what OOMs the two-slot VM. It happens because `buildCommand` (`selfhost/driver/build.byn:238`) keeps the compiled `Ctx`, the lowered tree and every emit temporary alive in `General` while `t9Build` (`selfhost/driver/cache.byn:321`) runs zig.

`work/todo.md:772-777` lists six follow-ups. This plan does them in four phases, one branch each, each merged `--no-ff` into dev in order and left unpushed. Release relevance: the 0.3.0 gate records the stage-2 build's peak RSS (last figure 2.94 GB), and Phase B lowers it on Linux.

Pattern from plans 012–014: `using let arena = Arena()` and `provide allocator: arena { … }`. A `List`, `Map` or `StrBuf` keeps the allocator it was created with (`StrBuf()` and `List<T>()` bind `byn_context` at construction). **`context.allocator` cannot be used as a value**: the parser rejects it with BYN1002. Strings therefore leave an arena only by being appended to a `StrBuf` or `List` created before the `provide`.

**Fable verified (2026-11-14): 12 corrections applied.** The two that change scope:
- **macOS does not return freed arena chunks to the OS.** Fable measured RSS at 1,050 MB before the free and 1,050 MB after; it falls to 3.5 MB only with `MallocLargeCache=0`.
- **Phase C writes into `Ctx` through three type interners.** These cannot be copied at the cprint write sites.

## Phase A: review LOWs (`fix/q31-followups-small`)
1. **`c.sink` guard** (todo:775) in `t42AnalyzeRegions` (`region.byn:199`): `if c.sink >= 0 { analyzeRegions(ref c, for: fn); return }` before the arena.
   - xUnit test: `SelfhostSemanticsHarness` with `pushBag`/`popBag`, the same pattern as `SelfhostSemanticsT2Tests.cs:207`. It checks that the bag's diagnostics survive.
   - This test passes with or without the guard (freed memory still prints). **The regression proof is the ASan run:** remove the guard and ASan reports a use-after-free.
   - The guard also covers `c.quiet` (`diag.byn:34`).
   - Result: the xUnit test is a regression gate after all. A `General` churn after `popBag` reuses the freed chunks, so without the guard 10 of 73 rows print freed memory and fail; no ASan run is needed.
2. **`pairs`/`returns` clear** (todo:777). Use Fable's construction: a `ref this` method `f`, declared before `g`, stores one parameter into `this` and calls `this.g(q)`, and `g` stores its parameter into `this`. A caller then stores a short-lived `q` into `f`.
   - Expected: with the clear, the caller gets the region diagnostic; without it, none.
   - New region `diag/` case with its expected output taken from the C#. Break-test: drop the clear and the golden differs.
   - Unconfirmed: whether `q → this` reaches `f`'s pairs from `g`'s summary (`region2.byn:351`, `:493`). If it does not, the LOW stays, with the attempt recorded.
3. **Linux sampled break-tests** (todo:776): `CheckOfTheDriverStaysBounded` via PeakSampler on bayan-test01 (user bt), with each arena reverted alone. Figures go into the test message and `docs/memory-leaks.md`.

## Phase B: free the frontend before the C compiler (`fix/q31-frontend-before-cc`)
One arena over compile, emit and out-dir prep, in `buildCommand` and in the run path (`build.byn:343-352`).

**Computed before the block:** `target` (`:255`), `symbols`, `o`, `key`, `d`. Nothing in the block writes `d`.

**Created before the block and filled inside it** (StrBufs, plus plain values):
- the C source;
- the output path (a `StrBuf` plus a `has` bool in the run path, where it is `string?`);
- the program name (`programName(ref compiled, …)`, read at `:283` on every non-JSON success);
- `shown`, the `:279` text that combines `manifest`, `displayRoot` and `output`;
- `parseTime`, `checkTime` and `emitTime`.

**Inside the block:**
- `reported` is declared there, so no General list holds arena strings.
- Every failure path that reads `Ctx` returns from inside the block: `t26Failed`, `refuseLibrary`, and `--emit-c` printing. `return` inside `provide` is already used at `driver/main.byn:296`.

`test.byn:256`, `mutate.byn:81` and `dist.byn:140` do not match this shape: they read `compiled` after the build. They go to `work/todo.md` with Fable's line lists.

**bayan's own peak may rise.** Inside an arena, `byn_arena_resize` (`bayan-rt.c:1453`) always takes a new block and leaves the old one behind. Every growing `Ctx` list and the `protos`/`bodies` StrBufs (`program.byn:16`) therefore keep all their earlier capacities until the block ends.
- Gate: measure bayan-alone peak before and after on both hosts.
- An increase of up to 10% is accepted and recorded. Above that is a stop for a decision.

**Test** `SelfhostDefaultBoundsTests.BuildFreesTheFrontendBeforeTheCCompiler`:
- Runs on Linux only; macOS returns early with a reason (it does not free, see Context), and Windows already returns early at `:109`.
- `BAYAN_CC` is a fake compiler script that **appends** `ps -o rss= -p $PPID` and exits 1. The parent is bayan: it spawns the compiler directly, with no shell between.
- The first calls are `<cc> --version` and then the runtime-object compile (fresh `BAYAN_CACHE`); both happen after the block. The message says these are the sample points.
- The bound is set after measuring on the VM.
- Break-test: revert the arena on the VM; the test must fail.

**Measure.**
- On the VM: bayan alone, and the combined host peak during a real-zig `build` (a sampler summing bayan and its child). Expected: about 2.4 GB → about 1.7–1.8 GB.
- On macOS: record that the combined peak does not fall, and why.

**To `work/todo.md` (user chose Linux-only, 2026-11-14):** large arena chunks via `mmap`/`munmap` in `bayan-rt.c`, so macOS gives the memory back too. That touches `src/runtime/bayan-rt.c`, the embedded `runtimeSource` and C# parity, so it is out of this plan.

## Phase C: `t6EmitFunction` arena, deferred (user chose C2, 2026-11-14)
**Decision:** C2. No code changes. The audit below goes into `work/todo.md`, and todo:773 and todo:774 stay open with it attached. The work is folded into the Phase A branch's todo commit.
Fable's audit found two kinds of write:
- **16 string-carrying writes into `CCtx`:** `common.byn:150,151,235,236,242`, `data.byn:11,12,24,42,62,80`, `program.byn:239,240,317` and `types.byn:319,320`. Plus `lineStarts` and `lineFile` (`func.byn:99-104,144`). `CCtx`'s collections are already bound eagerly (`program.byn:9`), so the old "bind first" step is dropped.
- **Three interners that write into `ref Ctx c` on a miss:** `internTuple` (`types.byn:533`, via `common.byn:58,124` and `func.byn:34`), `internOptional` (`types.byn:443`, via `helpers.byn:227`) and `errorUnionOf` (`types.byn:584`, via `common.byn:67`). They build lists in the current allocator, so the plan's stop condition fires as written.

**Option C1:** a caller-owned `keep` arena, created by the driver and outliving `compiled`.
- `cprint.emit` gains a `keep` parameter.
- The 16 `CCtx` sites copy their key and value with `s.copy(to: keep)`.
- The four interner calls run inside `provide allocator: keep { … }`.
- The `lineStarts` refresh moves outside the per-function arena.
- `EmitCOfTheDriverStaysBounded` (todo:774) is added if the margin is at least 40 MB.

**Option C2:** no code change. The audit goes to `work/todo.md` and C is closed as "stop condition hit".

**Checks under C1:**

- ASan clean over the driver and every region `diag/` case, each in its own `tmp/` directory.

- **Implementation:**
  - Wrap the single call at `generics.byn:207` in an arena with plan 014's `t42Mark`/`t42Undo`. On any diagnostic, rerun the analysis in General. A program with effect diagnostics therefore saves nothing; the driver saves memory.
