# Plan 018 (proposal): group the root of `docs/` by purpose

Status: proposed (waiting on the user; nothing below is implemented)
Release: unscheduled
Sources: the docs reorganisation proposed during the plan 017 session (subfolders `reference/`, `planning/`, `design/`), never answered; user 2026-11-15: "Write proposal only".

## Problem
`docs/` has 49 files at its root and 12 subfolders. Three kinds of doc sit side by side there:
- 21 release docs (`Version:` header);
- 3 record docs (`Status:` header);
- 14 snapshot docs (`Snapshot:` header);
- the generated `DIAGNOSTICS.md` and `STATUS.md`, `diagnostics-allocated.txt` and the 2.3 MB `suq-reference-app.zip`.

A reader looking for the language reference has to pick it out from design rounds, Sūq reports and the progress log.

## Proposed tree
`git mv` only: history follows every file (`git log --follow`, `git blame`), the same as plan 017. File names stay as they are (option A below).

A new `docs/README.md` lists each folder in one line, with links to the spec, the grammar, the style guide and `STATUS.md`. After the move the root holds only that README and the folders.

## What has to change with the move
References were counted with `git grep -l`, outside `docs/export/` and `docs/misc/`:

- **The top six:** `bayan-questions.md` is cited in 94 files, `bayan-spec.md` in 61, `bayan-progress-log.md` in 58, `bayan-milestones.md` in 39, `bayan-grammar.md` in 35 and `memory-leaks.md` in 32. About 700 path mentions in total.
- **Scripts that hard-code paths:**
  - `scripts/release/version.sh`: `bayan_release_docs` and `bayan_header_docs`;
  - `scripts/docs/check.sh`, `check-history.sh` and the `gen-*.sh` generators, including their `--write` targets;
  - `scripts/release/package.sh`, which maps the files to `share/doc/bayan/SPEC.md` and so on;
  - `cut.sh` and `next-dev.sh`;
  - the plan-strings and Q-id lookups, which read `bayan-questions.md`;
  - the C# tests that read docs (the `DiagnosticCodes` page checks, `ReadmeCommand`);
  - 108 files under `scripts/`, `csharp/`, `src/` and `.github/` name some `docs/` path.
- **`AGENTS.md`** names `docs/bayan-spec.md`, the handoff, `docs/bayan-library-tiers.md` and the progress log.
- **The release docs tarball** keeps each doc's path below `docs/`, so the 0.3.2 tarball's layout would differ from 0.3.1's. `share/doc/bayan/SPEC.md` and the other short names do not change.
- **Links from outside the repo:** GitHub URLs to `docs/bayan-spec.md` and the other moved files break. Nothing in the repo can redirect them. The site (bayan.run) is not published yet.

## Options
- **A. Move only, names unchanged (recommended).** About 45 renames plus the reference rewrites. Every old name still finds its file with `git log --follow`, and anyone who knows a file's name can still find it.
- **B. Move and drop the `bayan-` prefix** (`reference/spec.md` and so on). The paths are shorter, but every name changes as well, and `bayan-spec.md` and `spec.md` look like two files in old links and commit messages. It touches the same files as A and is harder to search.
- **C. Leave it.** Add only `docs/README.md` as an index. One file, nothing breaks, and the clutter stays.

Record docs (plans, decisions, revisions, audits) and snapshot docs: under A or B their path mentions are rewritten too, so every link in the repo resolves. `docs/export/` is the one exception: it is a snapshot of 821afa40 and keeps its text.

## How it would be done (A)
1. A branch off dev. One commit holds the `git mv`s only, so that rename detection is 100% and the commit can go into `.git-blame-ignore-revs` if the style-guide work adds that file.
2. A second commit rewrites the paths: a `sed` over every tracked text file for each old → new pair, with exact matches only, followed by the script lists and `AGENTS.md`.
3. Checks:
   - `scripts/docs/check.sh`;
   - `git grep` for each old path finds nothing outside `docs/export/`;
   - a link check over the markdown;
   - every ci.yml step on mac (`/bin/bash` 3.2), bayan-test01 and wp1;
   - a `cut.sh` dry run in a scratch clone, to show the docs tarball contents.
4. A `## [Unreleased]` CHANGELOG line naming the new folders, so the 0.3.2 notes say where the docs went.

Estimate: about 2 hours plus one CI round on the three hosts.
