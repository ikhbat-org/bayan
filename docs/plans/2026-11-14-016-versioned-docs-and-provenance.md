# Plan 016: every doc versioned, a spec index, and a feature history

Status: open (approved by the user 2026-11-14, "Full, after the split"; starts when the handoff split lands)
Release: 0.3.0 (docs only; no compiler change)
Sources: user request 2026-11-14; revision 0020 (the versioned-spec rule this extends); `docs/RELEASING.md`.

## Goal
Anyone can tell, from the files alone:
- which version of the software each document describes;
- which feature specs are built and which are still to be built;
- where each feature came from, why it changed, and why a feature was not built.

## Today
- Five docs carry a `Version: X.Y.Z (matches \`bayan --version\`)` header and ship in the release archives: SPEC, GRAMMAR, STYLE, DIAGNOSTICS and STATUS (`bayan_header_docs` in `scripts/release/version.sh`). They are checked by `scripts/docs/check.sh` (a)–(g).
- Git tags are the archive: the docs of a release are the files at its tag.
- Every other doc has no version, an inconsistent status line or none, and no source trail.
- Why a feature changed lives in `docs/revisions/`, Appendix A of the spec and `docs/decisions/`. Nothing links them back from the feature.

## Three kinds of doc

| kind | what | header (first ten lines) | changes when |
|---|---|---|---|
| **release** | describes the software as it is at a version: SPEC, GRAMMAR, STYLE, STATUS, DIAGNOSTICS, RELEASING, contributing, milestones, roadmap, not-planned, nice-to-have, questions, library tiers, concurrency, views, self-hosting, memory leaks, terminal style, typed dump, `docs/diagnostics/*.md`, `docs/security/*`, the spec index, the feature history | `Version: X.Y.Z (matches \`bayan --version\`)` | every release: `next-dev.sh` bumps them, as it does the five today |
| **record** | a decision made or work done at a point in time: `docs/specs/NNN-*/`, `docs/plans/`, `docs/decisions/`, `docs/revisions/`, `docs/audits/`, `docs/laws/`, the progress log | `Status:` (done / in progress / open / approved (not started) / deferred / superseded by X / rejected), `Release:` (the release it shipped in or targets, or `unscheduled`), and `Sources:` (Q-ids, revisions, decisions, user decisions with dates) | when its status changes; its body is history and is not rewritten |
| **snapshot** | kept for reference, not maintained: `docs/export/`, `docs/misc/`, design rounds 2–4, the suq reports | `Snapshot: <date>; not maintained. Current text: <path>` | never |

## Spec index
- `docs/specs/README.md` is generated by `scripts/docs/gen-spec-index.sh` from each spec's header.
- It is one table: number, title, status, release, sources, and plan and tasks links.
- Sections: built, in progress, to be built (with target release), and rejected (linking `docs/bayan-not-planned.md`).
- check.sh (c) verifies it is current, as it does for DIAGNOSTICS and STATUS.

## Feature history
`docs/bayan-feature-history.md` (release kind) has one row per numbered SPEC section:
- where it came from: a design round, a revision or a Q-id;
- each change: the revision, what changed and why, in one line;
- the release it was built in, or its current `(not in X.Y)` tag;
- for rejected features, a section with reasons from `docs/bayan-not-planned.md`, Appendix A and the answered questions.

Rule going forward: a new revision adds its row in the same commit.

## Guards (`scripts/docs/check.sh`)
- **(a)**, extended: every release doc has the `Version:` header for `VERSION`.
- **(h)**, new: every record doc has `Status:`, `Release:` and `Sources:`, and `Release:` is a released version, `VERSION` or `unscheduled`. Every snapshot doc has `Snapshot:`.
- **(i)**, new: every `docs/revisions/NNNN-*.md` is cited in the feature history, and every numbered SPEC section has a row.
- Each guard has a case in `scripts/docs/check.test.sh` that fails when the guard is removed.

## Release archive
`bayan-X.Y.Z-docs.tar.gz` ships every release doc: the spec index, the feature history and CHANGELOG are added to today's six. `docs/RELEASING.md` "Generated docs" and "What CI checks" are updated to match.

## Steps
1. **Decision doc** `docs/decisions/2026-11-14-NNN-versioned-docs-and-provenance.md`, recording the three kinds and the rules above. Commit it with this plan. Done.
2. **After the handoff split lands**, writer W1 (`codegen`) does the following:
   - adds the headers to every doc, by kind;
   - extends `bayan_header_docs`, or adds a `bayan_release_docs` list, in `version.sh`, so `next-dev.sh` and `cut.sh` bump the new docs;

   - updates the docs archive list and RELEASING.

   Done when `check.sh`, `check.test.sh` and `cut.test.sh` pass, and each break-test fails.
3. **In parallel, after W1:**
   - Writer W2 builds `gen-spec-index.sh`, its test, `docs/specs/README.md` and the (c) wiring.
   - Writer W3 writes `docs/bayan-feature-history.md` from revisions 0001–0023, Appendix A, `docs/decisions/` and the answered questions, plus `scripts/docs/check-history.sh` with its test. The parent then adds the one-line call from check.sh as (i).
4. **Gates:** each writer is gated against this plan. Then the parent runs the following:
   - `bash scripts/docs/check.sh`;
   - every `scripts/docs/*.test.sh`;
   - `cut.test.sh`;
   - `laws-check.js --run`;
   - `structure-audit.js`;
   - a `review` worker.

   The work merges `--no-ff` into dev, unpushed.
