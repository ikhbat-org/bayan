## Rules for every branch

Turn each into a `diag/` golden case (the expected diagnostic), or a `run/` case when the probe is a runtime crash that the fix must turn into a diagnostic. It must fail before the fix. Controls (`k*`) become cases that must stay clean.
2. **Self-check.** `bayan check src` plus examples and std. A true positive in the compiler's own code is fixed in a separate commit on the same branch; a false positive stops the branch for a design call.
3. **ASan.** Re-run every probe under ASan after the fix: no reports.
4. **Tests.** Only the selectors touched, locally (`--only 'diag/region/'` etc.); the full suite on wp1. Break-test each fix (`git checkout --`, a length-changing edit).
5. **Bounds.** `bayan check --package $PWD/src $PWD/src/driver` on mb1, median of 3, before and after. Baseline v0.4.0: 4.55 s, 456 MB max RSS. Stop on time > 5.0 s or RSS > 480 MB (the bounds test's macOS limit is 520 MB). In A, measure after each item.

## F — eval sandbox (16 #1, #2)
**#1 escape.** `scripts/evals/llm-sandbox.sh:212-216`: after the program exits, the launcher (outside the sandbox) writes `$stdout.cut` and `$status` with symlink-following `>`, and reads `$stdout` (`wc -c <`, `head -c`). `tools/llm-eval.byn` passes `--write sample` (`launch(for: sample)`, `:146`) and puts every `--stdout`/`--status` under `sample` (`test.json`, `format.stdout`, `<out>.status`), so the candidate controls all of them (probe `c1/`: a file outside was overwritten with 1 MiB). macOS only: elsewhere `sandbox=none` and there is no confinement to escape.
- Fix:
  - `llm-eval.byn` creates `results = <outDir>/results/<task>/<n>` (next to `work/`, outside `sample`) and passes every `launch(…, to:)` path under it: `test.json`, `format.stdout` and any run-output path (grep `to: Path.combine(sample`). The evaluator reads results from there. Nothing is moved back into `sample`.
  - The launcher refuses (exit 2) when the directory of `--stdout` or `--status` resolves under `--write`, or when either path is itself a symlink. Compute `wdir` outside the Darwin branch for this.
  - The launcher's `work` dir (`:89`) is created with `mktemp -d` under `/tmp`, not `$TMPDIR`: the evaluator sets `TMPDIR` to `sample/tmp` (`llm-eval.byn:169`), which is inside `--write`.
- Test: `scripts/evals/llm-eval.test.sh`: three cases, each planting one of `stdout`, `stdout.cut` or `status` in the old location as a symlink to an outside file; assert the outside file is unchanged. Plus: the launcher refuses a `--stdout` under `--write`, and a `--stdout` that is a symlink.

**#2 pending counts as passing.** `tools/llm-eval.byn:487` (`passes = tested.exitCode == 0 && !tested.limit`); `bayan test` exits 0 when every test is pending (`src/driver/test.byn:500, :550`).
- Fix: parse `test.json` (`src/driver/testreport.byn:72-130`). `passes = exitCode == 0 && !limit && summary.total > 0 && summary.passed == summary.total && summary.skipped == 0`.
  - A missing, empty, truncated or malformed report scores `passed: false`.
  - `limit` uses `summary.timedOut > 0` instead of `contains`.
  - `skipped` counts unchanged tests, and the cache (`BAYAN_CACHE` = `sample/cache`) is under `--write`, so a skip never passes.
  - The `bayan test` exit code is unchanged.
- Test: the `c2/` fixture (8 tests, `pending: 8`) scores `passed: false`; so do an empty report, a truncated one and one with `skipped > 0`.
- Rescoring (decided): rescore the 28 past `Check: tests` results from their stored `test.json` by the same rule. A task with no stored file is `unverified`. Rescoring only turns passes into fails. Log old and new counts.

## E — conformance shape (06 #2)
`conformance.byn:501-514` `t14SameShape` compares kind, static, return, parameters and `fails`, but:
- (a) receiver states, `becomes` and `move this` are never compared. Conformance copies `becomes`, `refThis` and `moveThis` to the interface's view (`:431-433`) but compares only `isMutating` (`:306`, `.refThisMismatch`). Receiver states are not on `FunctionSymbol`: they live only on the parser's `FunctionDecl.receiverStates`, resolved by `t22DeclFacts` (`states.byn:35`) and `receiverStates()` (`:321`).
  - An interface method may also declare a receiver state and `becomes`, and the names are never resolved: `checkStateNames` (`declare2.byn:262`) walks only structs. Checked on dev: all three combinations are accepted.
- (b) `return true if own.infersErrors || expected.infersErrors` (`:511`) accepts any inferring witness.
- Decision: an interface member may not declare a receiver state or `becomes`. An interface has no `states` block, so the names cannot resolve. A caller through `T: IDoor` or a `dyn` has no state facts to check a requirement against, and cannot track a transition. Interfaces with states would be a spec revision.
- Fix (a):
  1. `checkStateNames` also walks interface members. A receiver state or `becomes` there reports BYN7007 (unknown state; the interface has none). No new code.
  2. Next to the `:306` check: a witness with a receiver-state requirement (from `t22DeclFacts`) or a `becomes` does not conform. Report the mismatch code, with a note naming the field.
  3. `moveThis`: the witness has it exactly when the interface has it.
- Fix (b): `checkConformances` (`generics.byn:121`) records each (witness, expected) pair that took the `infersErrors` shortcut in `Ctx`. A new `t14CheckInferredWitnesses(ref c)` runs right after `inferErrorSets(ref c)` (`generics.byn:218`). For each pair whose `expected` declares its errors: every set the witness inferred is in `expected.errorSets`, and `expected.excludedErrors` names no variant of an inferred set (inference adds whole sets, `generics.byn:1323-1327`).
- Self-check std/examples first. A std interface member that declares a state or `becomes` makes this a breaking change: stop for a design call.
- Tests: `diag/conformance/`:
  - interface `ref this is .ajar` with `becomes .shut` → BYN7007 at the interface;
  - interface `ref this`, witness `ref this is .ajar` with `becomes .shut` → mismatch;
  - `move this` on one side only → mismatch;
  - inferred-set overflow; an inferred set with an excluded variant → mismatch;
  - controls: interface `ref this` with a plain `ref this` witness → clean; inferred ⊆ declared → clean.
- Name test states `ajar`/`shut`: `Door.open { … }` currently gives BYN1005 although `open` is only contextual (`Keywords.cs:10`), a parser bug. File it in `todo.md`; not part of this plan.

## A — region soundness (05 #1–#5, #10, #11)
Every probe "checks clean", then crashes under ASan or debug-panics.
- Arena: `t42AnalyzeRegions` (`region.byn:221`) runs each function in its own `Arena`. It skips the arena when `c.sink >= 0` and reruns in General when `t42Undo` reports persisted data (`T42Mark` covers diagnostics, locals and `changedFieldsKeys`). So state kept in `Regions` costs time, not peak RSS. Anything new kept in `Ctx` must be added to `T42Mark`/`t42Undo`, or it will point into a freed arena.

1. **#1 fixed point** (`region.byn:446-449`). The analysis is flow-insensitive and monotone:
   - `iterateRegions` (`:632`) runs a loop body once.
   - Every store into a local unions (`t41StoreBorrow`, `region2.byn:528`); storing a value that borrows nothing changes nothing. `referBorrow` (`:735`) only ORs. `unionBorrow` (`region.byn:151`) drops duplicates (`t25AddRegion`, `t25AddOwner`). `t25Merge` (`:186`) keeps the minimum lends `at`.
   - So `c1` needs a third pass: `return b` comes before `b = a` in the text, and each pass carries the chain one step.
   - Fix: repeat the collecting pass until a per-pass tuple of totals over all locals stops changing: region count, owner count, lends count, and the sum of lends `at`. Then do one reporting pass. The counts only grow, and with the lends count unchanged the sum only falls, so any change shows in the tuple.
   - The set of possible facts is finite, so the loop terminates. A cap of 64 passes is a guard against compiler bugs only: hitting it is `panic("internal error: region analysis did not converge")`. While developing, record the largest pass count on `src` and std and put it in the commit message.
   - Clear `r.loans`, `r.mutations`, and `pairs`/`returns` when `r.summary`, before each pass. They are appended in every pass (`region.byn:593`; `region2.byn:83,117,546,715,720,731`), so N passes would give N× entries and an O(M×L) `checkMutations`. Check whether `r.environments` is appended per pass (no `append` found by grep) and clear it too if so. `t25SetRestTail` updates in place.
   - Probe `c1`, control `k1`.
2. **#2 `ref`/`out` transfer** (`region2.byn:152-256`, `region.byn:422-431`).
   - (a) In the store-summary loop (`:154-185`), when `parameters[pair.source]` is `ref`/`out`, union `lendBorrow(arguments[pair.source])` into `source`, split by `mayLend` as at `:241-252`. Confirmed by `c2a`: `stash(ref a, to: out s) { s = a.span }` stores the source's storage.
   - The `out` target local must get a `Loan` (holder = the target local), or `c2b` (appends after the call) stays clean. Every owner in a stored value adds a `Loan` in `t41StoreBorrow`; check that the store-summary path reaches it.
   - Over-approximation: a callee that stores what a `ref` source holds, not its storage, also gets the lend. Watch `bayan check src`.
   - (b) `t41MayHold`: recurse into fixed arrays (`c2a`'s `i64[4]`).
   - (c) `t37SpanOrDynRef(callType)` at `:228` and `:235` becomes a `t37MayLendType` that also accepts optional, tuple and `string` wrapping (`c2c`'s `ReadOnlySpan<i64>?`; control `k2` gives BYN3004 today).
   - Closes Q745 (`todo.md:456-457`).
3. **#3 `provide` context on user `uses alloc` results** (`:257-282`).
   - Effects run before regions (`generics.byn:219` vs `:222`, `:245`), but `t42AnalyzeEffects` runs in an arena and keeps only diagnostics (`effects.byn:82-100`).
   - Fix: allocate a `List<bool>` "allocates" per FuncId in General before the effects arena. `analyzeEffects` fills it; the effects-side `t42Undo` leaves it alone (or the second run refills it). Regions only read it.
   - Regions then union `r.contexts.last` when the callee allocates and `containsList || mayHoldHeap(callType)`.
   - Reading only declared `uses` is not enough: it misses inferred functions, and treating every inferred function as allocating reports on `id(move xs)`.
   - Depends on D.
   - Break-tests (run on a scratch build, `--only 'diag/'`; each removes code, so the length changes):
     - `region2.byn` `callBorrow`: drop `|| mayBorrow(ref c, for: callType, by: ref seenHeap)` → `diag/region-provide-declared`, `-inferred`, `-transitive` fail.
     - `effects.byn` `analyzeEffects`: delete the `for fn in functions` loop that fills `c.allocates` → the same three fail.

4. **#4 loans** (`region2.byn:602-618, 753-841`), one sub-commit each, `bayan check src` and bounds after each:
   - (a) back-edge (`c4a`). A loan made inside a loop survives into the next iteration. Each `Loan` also records `scopeEnd`, the end of the block holding the statement that created it. A use `u` of the holder is dominated by the loan when `created < u < scopeEnd`; in structured code that statement runs before `u` on every path to `u`. For a loan L in loop P, with the holder declared outside P and a mutation M of the owner inside P: conflict if the holder has a use in P not dominated by L.
     - `c4a` (use before `s = xs.span`) → reported.
     - `for { xs.append(i); s = xs.span; print(s[0]) }` → clean (the use is dominated).

   - Highest false-positive risk. Fable reviews (a)–(d) before code is written.
5. **#5 copies** (`region.byn:874-886`, `region2.byn:441-444`): the `to:` form returns `allocatedFrom` (`:876`) and the no-argument form the context region (`:885`); both drop the elements' borrows. In both, when the element type may borrow, union the receiver's regions and owners. `stringCopy`/`strBufCopy`/`utf16Copy` are unchanged.
6. **#10 BYN3005** (MEDIUM, `region2.byn:120-150`): a root lookup `t41Root(ref r, c, e)` that is `rootLocal` (`:846-862`) plus: `.field` on a `.thisRef` receiver → `r.thisFields[field]` (the pseudo-local mutations already use, `:720`), and the `ref this` receiver as its own key at argument −1. Guard the name lookup at `:137` (`c.locals[root].name`) so that key prints as `this`. Probe: a `ref this` receiver aliasing a value argument.
7. **#11** (MEDIUM, `region2.byn:446-481`): `t41AllocatedFrom` uses `t41Root`. For a `this` field root: depth 0, region "this", owner `r.thisFields[field]`. Probe: `provide allocator: this.a { … }` then `this.a.reset()` → reported.
