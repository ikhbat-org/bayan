## Decisions

### 1. Payload ABI: runtime code + one general detail slot, wrapped at the call site (5.3h layout kept)

- The `byn_err` layout of 5.3h/Q311 is kept unchanged. The runtime keeps returning `uint32_t`; every builtin failing call that can carry a payload takes one extra out-parameter `int64_t* detail` (NULL allowed), the general "detail slot": the single integer payload of a builtin variant. `byn_io_run`/`byn_io_run_with` write the signal number for `BYN_IO_SIGNALED` and the timeout in ms for `BYN_IO_TIMEOUT`. Two codes are added to `bayan-rt.h`: `BYN_IO_SIGNALED 10u`, `BYN_IO_TIMEOUT 11u`, and `BYN_UTF8_INVALID_SEQUENCE 12u` for the reuse below. Nothing is added to `byn_process`.
- **Call-site wrapping reads the slot.** `CEmitter.cs` `case LFailingCall` (and `func.byn`'s mirror) becomes one mechanism for every builtin: declare `int64_t detail = 0;`, emit `err = (ErrorCType){ .code = call(…, &detail) };`, then for each detail-carrying variant `v` among the callee's `ErrorSets` emit `if (err.code == UINT32_C(v.Code)) err.p.e<v.Code> = { (<field C type>)detail };` (one line per variant: `.signaled` casts to `int32_t`, `.timeout` and `invalidSequence` keep `int64_t`). The three special-cased helpers stop building structs: `bynh_utf8_decode` returns `uint32_t` and writes `*detail = at`, same for `bynh_hex_decode` and the parse helper (their codes stay emitter-known because `ParseError` is numbered after user sets); `Utf8Decode`, `HexDecode`, `IntParse` leave the exception list, which is deleted. `Io.runBatch` passes NULL (no detail variant in its path).
- **Marker of detail-carrying variants.** C#: `ErrorVariantSymbol.Fields` of a builtin set with exactly one primitive field, enumerated by a new `Builtins.DetailVariants` property (`IoError.signaled`, `IoError.timeout`, `Utf8Error.invalidSequence`, `ParseError.badDigit`) that `LFailingCall` consults; `DeclareBuiltinVariants` asserts "a built-in payload is one primitive or `Millis`". Selfhost: `selfhost/semantics/builtins.byn` `detailVariants` (same four, resolved through `t9ErrorSet`). Runtime header: a `/* detail-carrying: writes *detail */` block listing `BYN_IO_SIGNALED`, `BYN_IO_TIMEOUT`, `BYN_UTF8_INVALID_SEQUENCE` beside their defines; `ParseError` has no define (not runtime-numbered).
- **`Utf8Error` byte position (5.4b) reuses it.** `Utf8.decode` stops being special: `bynh_utf8_decode(bytes, out, &detail)` calls `byn_utf8_invalid_at`, returns `BYN_UTF8_INVALID_SEQUENCE` with `*detail = at`, and the call-site wrap fills `.p.e12`. `Io.readText`/`Io.stdin.readAll` keep `invalidUtf8` (no position; unchanged). A `ParseError.badDigit` follows the same wrap with its emitter-known code.
- Layers that change: binder (`Builtins.cs` `IoErrorSource`, `IoRun` parameters, `DetailVariants`; `Compilation.cs` `DeclareBuiltinVariants`), C emitter (`CEmitter.cs` `LFailingCall`, `IoRun`, `Utf8Decode`, `HexDecode`, `IntParse` helper cases), runtime (`bayan-rt.{h,c}`), selfhost (`builtins.byn` `ioErrorSource`, `runParameters`, `detailVariants`; `selfhost/emitter/cprint/func.byn`, `expr.byn`; generated `selfhost/driver/runtime.byn`). Lowering (`src/Bayan.Lowering`) is untouched: `LFailingCall` already carries the error local. No interpreter.
- Rejected: a `byn_process`-specific `signal` field (not reusable by `Utf8Error`, leaves three helper special cases); returning `byn_err` from the runtime (layout is per program); a `byn_io_status` struct return (changes every `BYN_IO_*` caller's signature for one integer); encoding the signal in the code (`sig << 8`): in-band, exactly what 006 forbids.

No std or builtin `Millis` exists. ### 5. Process tree kill

- POSIX: when `timeout_ms >= 0`, the child starts in its own process group: `posix_spawnattr_t` with `POSIX_SPAWN_SETPGROUP` and `posix_spawnattr_setpgroup(&attr, 0)` on the `posix_spawnp` path; `setpgid(0, 0)` before the `dup2`s in `byn_fork_exec`'s child. Without a timeout the group is unchanged (a child in a new group that reads a shared terminal stdin would be stopped by SIGTTIN; keep today's behaviour there). The capture loop's `poll(fds, 3, -1)` takes `remaining = deadline - byn_io_monotonic_nanos()` in ms (clamped to `INT_MAX`); on `poll == 0` it does `kill(-pid, SIGTERM)`, marks `timed_out`, resets the deadline to now + grace; on the second expiry `kill(-pid, SIGKILL)` and the deadline to now + 5 s (the C# oracle's bound); on the third expiry the loop closes our pipe ends and stops draining (an escaped grandchild cannot hold us). Then `waitpid(pid)` reaps as today. Every `kill`/`setpgid`/`posix_spawnattr_*` return is checked (W1); `libc-uses.txt` rows in the same commit.
- Windows: when a timeout is given, `CreateJobObjectW(NULL, NULL)`, `SetInformationJobObject(JobObjectExtendedLimitInformation, JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE)`, `CreateProcessW` with `CREATE_SUSPENDED` added to its flags, `AssignProcessToJobObject(job, pi.hProcess)`, `ResumeThread(pi.hThread)`, then `CloseHandle(pi.hThread)` (today's close moves after the resume). The helper waits `WaitForSingleObject(pi.hProcess, timeout_ms)` *before* joining the drain threads (today it joins first); `WAIT_TIMEOUT` → `TerminateJobObject(job, 1)` and an INFINITE wait on the process; the job kill closes every holder of the pipes, so the drain joins end. The joins get a 5 s bound only in the timed-out case; `CloseHandle(job)` last. Every return checked.
- One mapping function, non-static, compiled on every host:
  `uint32_t byn_wait_status(int outcome, uint32_t raw, int64_t timeout_ms, int32_t* code, int64_t* detail)` with `outcome` one of `BYN_WAIT_DONE`, `BYN_WAIT_FAILED` (waitpid non-EINTR / `WaitForSingleObject` failed), `BYN_WAIT_QUERY_FAILED` (`GetExitCodeProcess` failed), `BYN_WAIT_TIMED_OUT`. Precedence: `FAILED`/`QUERY_FAILED` → `BYN_IO_OTHER` (raw ignored, so 0 and 259 never leak); `TIMED_OUT` → `BYN_IO_TIMEOUT` with `*detail = timeout_ms`; then on POSIX `WIFSIGNALED(raw)` → `BYN_IO_SIGNALED` with `*detail = WTERMSIG(raw)`, else `*code = WEXITSTATUS(raw)`; on Windows `*code = (int32_t)raw`. `detail` may be NULL. `byn_process_finish` takes `(streams, outcome, raw, timeout_ms, out, detail, alloc)`, calls `byn_wait_status` first, and only on 0 checks UTF-8 (`invalidUtf8`) and copies: wait failure > `.timeout`/`.signaled` > `invalidUtf8` > success. Streams are freed on every path.

### 6. C# reference and the driver ports

`src/Bayan.Cli` keeps .NET `Process`; nothing in `CliApp.cs`, `Doctor.cs` or `Scaffold.cs` changes. The self-hosted `test.byn` (017 T11) calls `Io.run(exe, args, env: {"BAYAN_COVERAGE": prefix}, timeout: Millis(ms))` and maps `IoError.timeout` to the timed-out outcome; `mutate.byn` (T13) sets `BAYAN_MUTANT`/`BAYAN_SITE_REACH` the same way.
