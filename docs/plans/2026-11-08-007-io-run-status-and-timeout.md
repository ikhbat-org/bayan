- **The fail-open paths are the same on every branch.** POSIX: `int status = 0; while (waitpid(pid, &status, 0) < 0 && errno == EINTR) {} code = WIFSIGNALED(status) ? 128 + WTERMSIG(status) : WEXITSTATUS(status);` at the tail of `byn_io_run_with` (015) / `byn_io_run` (fs-slice). No `posix_spawnattr_*`, `setpgid`, `kill`, Job object or `TerminateProcess` exists in the runtime or in `src/runtime/libc-uses.txt`.

## Decisions

### 1. Payload ABI: runtime code + out field, payload built by the emitted helper

- The runtime keeps returning `uint32_t`. Two codes are added to `bayan-rt.h`: `BYN_IO_SIGNALED 8u`, `BYN_IO_TIMEOUT 9u`. `byn_process` gains `int32_t signal;` ("set when the call returns `BYN_IO_SIGNALED`; 0 otherwise"). The `.timeout` payload is the caller's own `timeout` argument, so nothing travels back for it.
- The emitted `Io.run` helper (`bynh_io_run`/`bynh_io_run_with` in `CEmitter.cs` `case BuiltinFunction.IoRun` and `selfhost/emitter/cprint/expr.byn` `case .ioRun`) returns `ErrorCType` like `bynh_utf8_decode`: it passes a local `byn_process` when `out` is NULL, then `code == BYN_IO_SIGNALED` becomes `{ .code = 8, .p.e8 = { p.signal } }`, `code == BYN_IO_TIMEOUT` becomes `{ .code = 9, .p.e9 = { timeout.value } }`, anything else `{ .code = code }`. `IoRun` joins the `LFailingCall` list in `CEmitter.cs` and `func.byn`. `Io.runBatch` keeps the bare-code wrapper (no signal, no timeout; a failed wait is still `other`).
- Layers that change: binder (`Builtins.cs` `IoErrorSource`, `IoRun` parameters; `Compilation.cs` `DeclareBuiltinVariants`), C emitter (`CEmitter.cs` `LFailingCall`, `IoRun` case), runtime (`bayan-rt.{h,c}`), selfhost (`selfhost/semantics/builtins.byn` `ioErrorSource` and `runParameters`; `selfhost/emitter/cprint/func.byn`, `expr.byn`; generated `selfhost/driver/runtime.byn`). Lowering (`src/Bayan.Lowering`) is untouched: `LFailingCall` already carries the error local. No interpreter.
- Rejected: returning `byn_err` from the runtime (layout is per program, see Findings); encoding the signal in the code (`8 | sig << 8`): in-band, exactly what 006 forbids.

### 2. Variant numbering

`signaled(i32 signal)` = 8 and `timeout(Millis after)` = 9, appended after `unsupported`. `Utf8Error.invalidSequence` 8 → 10, user variants 9 → 11, `ParseError` unchanged relative to user sets. Both variants are declared in phase A (below) so the shift happens once. Regenerate with `BAYAN_UPDATE=1 dotnet test`; the expected diff is empty in `run/` and confined to any `emit/` or `typed/` case that prints a code (none found by grep; review the diff rather than assume).

### 3. `Millis`

No std or builtin `Millis` exists. Add a builtin distinct type: `BuiltinKind.Millis` / `BuiltinType.Millis` in `Types.cs`, resolved by name in `TypeResolver.cs` next to `"IoError"`, C type `int64_t` (`CEmitter.cs` `CType`, `Key` = `"millis"`, equality and format arms), constructed `Millis(n)` and unwrapped `i64(t)` through the existing primitive-conversion call path in `BinderCalls.cs`; no literal suffix, no arithmetic, no comparison beyond `==` (spec §3.4 "a unit without arithmetic"). `DeclareBuiltinVariants` accepts it beside `PrimitiveType.ByName`. Selfhost: `builtins.byn` type table, `common.byn` C type switch. **User-visible addition**: a new type name in every program's scope; a user type named `Millis` shadows it like `IoError` does (`TypeResolver` checks the module first). Rejected: a spec `unit` (not implemented, Q331); a bare `i64` (the decision names `Millis`).

### 5. Process tree kill

- POSIX: when `timeout_ms >= 0`, the child starts in its own process group: `posix_spawnattr_t` with `POSIX_SPAWN_SETPGROUP` and `posix_spawnattr_setpgroup(&attr, 0)` on the `posix_spawnp` path; `setpgid(0, 0)` before the `dup2`s in `byn_fork_exec`'s child. Without a timeout the group is unchanged (a child in a new group that reads a shared terminal stdin would be stopped by SIGTTIN; keep today's behaviour there). The capture loop's `poll(fds, 3, -1)` takes `remaining = deadline - byn_io_monotonic_nanos()` in ms (clamped to `INT_MAX`); on `poll == 0` it does `kill(-pid, SIGTERM)`, marks `timed_out`, resets the deadline to now + grace; on the second expiry `kill(-pid, SIGKILL)` and the deadline to now + 5 s (the C# oracle's bound); on the third expiry the loop closes our pipe ends and stops draining (an escaped grandchild cannot hold us). Then `waitpid(pid)` reaps as today. Every `kill`/`setpgid`/`posix_spawnattr_*` return is checked (W1); `libc-uses.txt` rows in the same commit.
- Windows: when a timeout is given, `CreateJobObjectW(NULL, NULL)`, `SetInformationJobObject(JobObjectExtendedLimitInformation, JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE)`, `CreateProcessW` with `CREATE_SUSPENDED` added to its flags, `AssignProcessToJobObject(job, pi.hProcess)`, `ResumeThread(pi.hThread)`, then `CloseHandle(pi.hThread)` (today's close moves after the resume). The helper waits `WaitForSingleObject(pi.hProcess, timeout_ms)` *before* joining the drain threads (today it joins first); `WAIT_TIMEOUT` → `TerminateJobObject(job, 1)` and an INFINITE wait on the process; the job kill closes every holder of the pipes, so the drain joins end. The joins get a 5 s bound only in the timed-out case; `CloseHandle(job)` last. Every return checked.
- One mapping function, non-static, compiled on every host:
  `uint32_t byn_wait_status(int outcome, uint32_t raw, int32_t* code, int32_t* signal)` with `outcome` one of `BYN_WAIT_DONE`, `BYN_WAIT_FAILED` (waitpid non-EINTR / `WaitForSingleObject` failed), `BYN_WAIT_QUERY_FAILED` (`GetExitCodeProcess` failed), `BYN_WAIT_TIMED_OUT`. Precedence: `FAILED`/`QUERY_FAILED` → `BYN_IO_OTHER` (raw ignored, so 0 and 259 never leak); `TIMED_OUT` → `BYN_IO_TIMEOUT`; then on POSIX `WIFSIGNALED(raw)` → `BYN_IO_SIGNALED` with `*signal = WTERMSIG(raw)`, else `*code = WEXITSTATUS(raw)`; on Windows `*code = (int32_t)raw`. `byn_process_finish` takes `(streams, outcome, raw, out, alloc)`, calls `byn_wait_status` first, and only on 0 checks UTF-8 (`invalidUtf8`) and copies: wait failure > `.timeout`/`.signaled` > `invalidUtf8` > success. Streams are freed on every path.

### 6. C# reference and the driver ports

`src/Bayan.Cli` keeps .NET `Process`; nothing in `CliApp.cs`, `Doctor.cs` or `Scaffold.cs` changes. The self-hosted `test.byn` (017 T11) calls `Io.run(exe, args, env: {"BAYAN_COVERAGE": prefix}, timeout: Millis(ms))` and maps `IoError.timeout` to the timed-out outcome; `mutate.byn` (T13) sets `BAYAN_MUTANT`/`BAYAN_SITE_REACH` the same way. One divergence is inherent in the decision: the C# reports the output captured before the kill, while `fail .timeout(after)` drops it (Question Q-a).
