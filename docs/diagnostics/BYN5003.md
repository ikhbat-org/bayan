# BYN5003: `tryX` with the wrong return type

**What.** A hand-written `tryX` returns something other than `T?` or `bool`, and the type has an `x()` that `fails`.

**Why.** `tryX` is reserved (spec §5.2, [grammar guide](../bayan-grammar.md) tree 4): it is the attempt form of `x() fails`, derived from it, and it returns `T?` (the value or `null`) or `bool` (whether it worked). A `tryX` with another return type reads as an attempt but does not report failure the way every other `tryX` does.

**Example.**

```
union error ParseError {
    empty
}
struct Reader {
    string text
    i64 parse() fails ParseError {
        return 0
    }
    i64 tryParse() => 0
}
```

**Fix.** Remove `tryParse` and call `try parse()`, or return `i64?`:

```
    i64? tryParse() => null
```

**Where this comes from.** `tryX` follows Arabic verb Form X (istafʿala), which adds the sense of attempting the act. See the [grammar guide](../bayan-grammar.md) §12.
