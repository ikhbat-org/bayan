# BYN2780: implicit copy of a unique value

**Message.** "implicit copy of a unique value: {0}"

**Help.** "write `move {0} with { … }` to give up `{0}`" (on a `with` that copies a `unique` value, `{0}` the copied variable).

**Why.** A unique value owns storage: a `List`, `Map`, `StrBuf` or `Owned`, a `unique struct`, a type parameter inside a generic body, or anything that holds one of these by value (a struct field, a union payload, a tuple, array, optional, `Untrusted` or `Result`). Copying it would leave two values sharing that storage, and growing or freeing one would leave the other pointing at freed memory. So storing an existing place of a unique type is rejected: a `let` or `var` initializer, an assignment, a field in a struct literal or `with`, an element added to a collection, a tuple, array or optional, an argument to a `move` parameter, or a `return` of anything but a local or `move` parameter (returning those moves them). A plain parameter of unique type is a read-only borrow, so storing it is a copy too. Fresh values (calls, constructors, literals, `copy(to:)`, `move x`) are never copies, and reading in place (members, indexing, `for`, `switch`, comparison, formatting, passing to a plain or `ref` parameter) is fine. A field of unique type cannot stand for an interface getter either: the getter's result belongs to the caller, so reading the field in its place would copy it.

**Example.**

```
var a = List<i64>()
a.append(1)
var b = a
```

**Fix.** Hand the value over with `move`, after which `a` cannot be used until it is assigned again:

```
var b = move a
```

or make an independent copy with `a.copy(to: alloc)` (for a `List`, `Map` or `StrBuf`), or share the original by passing it by `ref`. In a function that should own a parameter, declare it `move p`.

A `with` that copies a unique value from a local hands it over the same way: `let copy = move tx with { label: "copy" }` is `(move tx) with { … }`, since `with` binds looser than every prefix operator. `x = x with { … }` is already a move and needs no `move`.
