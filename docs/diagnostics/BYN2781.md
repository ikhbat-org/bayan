# BYN2781: use after move

**Why.** `move x` (or passing `x` to a `move` parameter) hands its value to a new owner, so `x` no longer holds anything. Reading it, calling a member on it or moving it again on any path after the move would touch storage that now belongs to someone else. A move in one branch of an `if` or `switch` makes the local unusable after the branches join, and a move inside a loop of a local declared outside it fails on the next iteration.

**Example.**

```
var a = List<i64>()
var b = move a
a.append(2)
```

**Fix.** Assign a fresh value before using the local again:

```
var b = move a
a = List<i64>()
a.append(2)
```

or move a copy instead, `move a.copy(to: alloc)`, and keep the original. In a loop, reassign the local before the next iteration.
