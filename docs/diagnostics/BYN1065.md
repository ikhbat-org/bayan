# BYN1065: function clauses out of order

**Why.** The clauses after a function's parameters have one order, so every signature reads the same way: `where`, `expects`, `uses`, `becomes`, `fails`. The code is raised once, at the first clause out of order.

**Example.**

```
i64 parse(string s) fails ParseError uses io { return 0 }
```

**Fix.** Put the clauses in order: `i64 parse(string s) uses io fails ParseError { return 0 }`. The diagnostic carries a machine-applicable fix that sorts the clauses, and `bayan format` applies it.
