# BYN0005: identifier not in normalization form C

**Why.** Unicode can encode the same visible letter in more than one way (`é` as one scalar or as `e` + combining accent). Two identifiers that look identical but differ in bytes would be different names. Bayan requires NFC so that names that look the same are the same.

**Example.**

```
let café = 1   // `e` followed by U+0301
```

**Fix.** Use the composed form. The diagnostic carries a machine-applicable fix; most editors also have a "normalize to NFC" command.
