# BYN1054: `try` covers more than the call that fails

**Why.** `try` covers the whole expression to its right, down to `??` (spec §8): one scope rule, with no exceptions to memorize. When the part that can fail is only a piece of that expression, the reader would take `try` to apply to the whole, so the compiler asks for parentheses around the failing piece.

**Example.**

```
i64 parse(string s) fails ParseError { return 0 }
i64 total(string s) fails ParseError {
    return try parse(s) + 1
}
```

**Fix.** Wrap the part that fails in parentheses, with `try` inside:

```
i64 total(string s) fails ParseError {
    return (try parse(s)) + 1
}
```

The diagnostic carries a machine-applicable fix. `bayan format` does not apply it: the code is a binder error, not an input form.
