# BYN2613: panic handler reads a `var`

**What.** A `defer panicking` body, or the function named by `Panic.handler`, reads a `var` declared outside it. `let` bindings, `is let` and `for` loop variables, and parameters are fine.

**Why.** A panic can happen half way through an update, so a `var` may hold a torn or stale value when the handler runs. A `let` binding, a loop or pattern variable, or a parameter was fixed before the handler was registered, so the handler sees what it was written against (spec §7.6).

**Example.**

```
var done = 0
defer panicking print($"{done} items written")
```

**Fix.** Copy the value into a `let` before the handler and read that, or leave it out of the report:

```
let total = items.length
defer panicking print($"writing {total} items failed")
```
