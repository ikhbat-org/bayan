# BYN5105: a count not named singular noun + `Count`

A lint: it never blocks a build. It checks the public API only, a `public` integer field or property of a `public` struct; a name the module keeps to itself is not checked (grammar guide §1, checker scope). A name under a rename attribute (`@json(name: …)`, `@column(…)`) is forced from outside and not checked.

**What.** An integer that counts items is named `<plural>Count` (`linesCount`), `num<Plural>` (`numLines`) or `numberOf<Plural>` (`numberOfLines`). The plural is one the checker knows: an irregular plural, a project noun's `forms` entry, or a regular plural of a known noun. Words before it stay (`totalLinesCount` → `totalLineCount`). `length` is the size name and is not a count.

**Why.** One spelling for every count: `lineCount` reads as "the count of lines", the way `lineItem` reads as "an item of the line" (revision 0021 Part 4, [grammar guide](../bayan-grammar.md) §14).

**Example.**

```
public struct Order {
    public i64 linesCount
    public i64 numLines
}
```

**Fix.** Singular noun, then `Count` (the machine fix renames the declaration; rename the callers with it):

```
public struct Order {
    public i64 lineCount
}
```

**Where this comes from.** A counted noun after a number word is singular in Arabic (tamyīz al-ʿadad, from eleven up), as in English "line count". See the [grammar guide](../bayan-grammar.md) §14.
