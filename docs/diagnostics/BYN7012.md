# BYN7012: assignment that changes the state

**Message.** `{0}` would change state here; a state changes only through `become`

**Help.** assign a value in the same state, or move the transition into a `becomes` method

**Why.** A state changes in place only through `become`, so every change shows in a `becomes` signature. A whole-value assignment to a `ref` parameter (or to `this`) whose type has states could swap the caller's value for one in another state without the caller knowing. It is allowed only when the target's type names exactly one state and the new value is in that state: `ref Order o` and `ref Order o is .paid or .shipped` can't be reassigned, since the callee does not know which state the caller had; `ref Order.paid o` can take another `Order.paid`.

**Example.**

```
struct Order {
    i64 id
    states {
        draft
        paid(i64 payment)
    }
}
void wipe(ref Order o) {
    o = Order.draft { id: o.id }
}
```

**Fix.** Assign a value in the state the parameter names (`ref Order.paid o` takes `Order.paid { … }`), write fields through a `ref this` method of the struct, or move the transition into a `ref this` method that declares `becomes .draft` and runs `become .draft`.
