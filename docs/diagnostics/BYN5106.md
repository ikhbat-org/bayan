# BYN5106: a doer type without its verb

A lint: it never blocks a build. It checks the public API only, a `public` struct or interface; a type the module keeps to itself is not checked (grammar guide §1, checker scope). A type under a rename attribute (`@json(name: …)`, `@column(…)`) is forced from outside and not checked, and neither is the standard library.

**What.** The last word of the type name is a doer or tool noun (`CsvParser` → `parser`), and no public member, static or instance, is named its verb or a derived form of it: `tryX`, `xInto` or `xOp`. The nouns are the built-in `parser`, `builder`, `reader`, `writer`, `recorder`, `encoder`, `decoder`, `scanner`, `loader`, `scheduler`, `renderer`, `formatter`, `handler`, `hasher` and `comparer`, each with its verb; `codec`, whose verb is `encode` or `decode` (either counts); and a noun derived from a project verb in `package.byn` by regular spelling (`upsert` → `upserter`). Irregular doer nouns, other words ending in "-er" (`Carrier`, `Ledger`, `Pointer`, `User`), function-type aliases and stored function fields are not checked.

**Why.** A type named for an act promises that act: a reader of `CsvParser` looks for `parse` (revision 0021 Part 4, [grammar guide](../bayan-grammar.md) §14).

**Example.**

```
public struct Table {
    public i64 rowCount
}

public struct CsvParser {
    public Table read(ref this) => Table { rowCount: 0 }
}
```

**Fix.** Name the member for the act, or rename the type for what it is:

```
public struct Table {
    public i64 rowCount
}

public struct CsvParser {
    public Table parse(ref this) => Table { rowCount: 0 }
}
```

**Where this comes from.** An agent noun (ism al-fāʿil, `kātib` from `kataba`) names the one who does the act of its root, as "parser" names the one who parses. See the [grammar guide](../bayan-grammar.md) §14.
