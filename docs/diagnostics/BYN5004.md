# BYN5004: too many unlabeled parameters

**Why.** A particle is part of a function's name: `copy(from: a, to: b)` says what each argument is for, where `copy(a, b)` leaves the reader to guess. A function has at most one unlabeled required parameter, the object; every other one starts with a particle (`from`, `to`, `until`, `through`, `at`, `by`, `for` or `as`). The receiver of a method never counts as the object. `bool` parameters, parameters with a default, `extern` declarations, operators, union and state payloads and laws are exempt.

**Message.** `{0}` has {1} unlabeled parameters; give each but one a particle

**Help.** keep one unlabeled parameter, the object

**Example.**

```
void transfer(i64 amount, i64 payer, i64 payee) {
    return
}
```

Each parameter besides the object is also reported as BYN5006.

**Fix.** Keep the object unlabeled and give the others a particle by meaning:

```
void transfer(i64 amount, from i64 payer, to i64 payee) {
    return
}
```

The diagnostic has no machine-applicable fix.
