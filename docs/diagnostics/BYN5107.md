# BYN5107: a tool that changes `this`

A lint: it never blocks a build. It checks the public API only, a `public` member of a `public` struct or interface; a name the module keeps to itself is not checked (grammar guide §1, checker scope). A type under a rename attribute (`@json(name: …)`, `@column(…)`) is forced from outside and not checked, and neither is the standard library.

**What.** The last word of the type name is a tool noun, `hasher`, `comparer` or `codec`, and a public member takes `ref this`.

**Why.** A tool does the same thing every time it is used: fixed settings in fields are fine, but a call does not change it. A type fed data step by step is a doer and should be named like one (revision 0021 Part 4, [grammar guide](../bayan-grammar.md) §14).

**Example.**

```
public struct Order {
    public i64 total
}

public struct OrderHasher {
    u64 seed
    public u64 hash(ref this, Order order) {
        seed += 1
        return seed
    }
}
```

**Fix.** Remove `ref this`, or rename the type as a doer if it is fed data step by step:

```
public struct Order {
    public i64 total
}

public struct OrderHasher {
    u64 seed
    public u64 hash(Order order) => seed + u64(order.total)
}
```

**Where this comes from.** A noun of instrument (ism al-āla, `miftāḥ` "key" from `fataḥa`) names the thing an act is done with, not the one who does it. See the [grammar guide](../bayan-grammar.md) §14.
