# BYN2612: not allowed in a panic handler

**What.** A `defer panicking` body, or the function named by `Panic.handler`, uses `try`, `return`, `break`, `continue`, an assignment or an allocation.

**Why.** A panic means the program is in a state it cannot trust, and handlers run on the way to aborting it (spec §7.6). Panic handlers can't recover: they cannot resume normal flow, fail, change state, or ask an allocator that may itself be broken for memory. They can only report, flush and release outside resources.

**Example.**

```
struct Db {
    i64 id
    string name
}
void log(string s) { }
void save(Db db) {
    var saved = 0
    defer panicking {
        saved = -1
        let note = $"save failed after {saved}"
        log(note)
    }
}
```

**Fix.** Write the report straight to `print`, `panic` or a `StrBuf` the handler was given, and read only `let` values:

```
struct Db {
    i64 id
    string name
}
void save(Db db) {
    let name = db.name
    defer panicking (p) print($"save to {name} failed: {p.message}")
}
```
