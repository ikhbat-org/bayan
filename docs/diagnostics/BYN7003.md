# BYN7003: `become` the signature does not declare

**Message.** `become` needs `becomes .{0}` on `{1}` (with another target: `become .{0}` is not declared; `{1}` becomes `.{2}`; for a `becomes` call on `this`: `{0}` calls `{1}`, which changes the state; declare `becomes` on `{0}`)

**Help.** add `becomes .{0}` to the signature of `{1}` (with another target: change the target to `.{2}`, or declare `becomes .{0}`; for a `becomes` call on `this`: add `becomes .{2}` to the signature of `{0}`)

**Why.** A transition is part of the method's signature: callers rely on `becomes .s` to know the state after the call. A `become` the signature does not declare would change the state behind their back. The same holds for a call on `this` to a method that `becomes .t`: it changes the caller's state, so the caller declares `becomes .t` too, and the call counts as its `become .t`.

**Example.**

```
struct Order {
    i64 id
    states {
        draft
        paid(i64 payment)
    }
    void pay(ref this is .draft, i64 amount) {
        become .paid(amount)
    }
}
```

**Fix.** Declare the transition: `void pay(ref this is .draft, i64 amount) becomes .paid { … }`. With no `becomes`, the diagnostic carries a machine-applicable fix that adds the clause. With another target, change the `become` or the `becomes` so they agree. For a `becomes` call on `this` (`void erase(ref this) { reset() }`), declare the callee's target on the caller: `void erase(ref this) becomes .draft { reset() }`; the fix adds the clause when the caller has no `becomes`. On a `move this` or plain `this` method, the fix also makes the receiver `ref this`, since BYN7010 rejects `becomes` without it.
