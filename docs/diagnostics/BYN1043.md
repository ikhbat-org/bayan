# BYN1043: declaration and local binding in the wrong order

**Why.** Declarations put the type first (`Sku sku`, `Grams weight(Order order)`); local bindings put the name first (`let w: Grams = 0g`). One code covers both directions, with one message form each. A name-first declaration reads "`{0}: {1}` is an input form; write `{1} {0}`", and a name-first return reads "`{0}(…) -> {1}` is an input form; write `{1} {0}(…)`". A type-first local reads "`{0} {1}` is an input form; write `let {1}: {0}`". A typed loop variable follows the local rule: `for T x in e` reads "`for {0} {1}` is an input form; write `for {1}: {0}`".

**Message.** `{0}: {1}` is an input form; write `{1} {0}` (a name-first declaration); `{0}(…) -> {1}` is an input form; write `{1} {0}(…)` (a name-first return); `{0} {1}` is an input form; write `let {1}: {0}` (a type-first local).

**Help.** put the type before the name; declarations are type-first (declaration); put the return type before the name (return); write `{2} {1}: {0}`; local bindings put the name first (local, `{2}` is `let` or `var`).

**Example.**

```
f() -> i32 { return 0 }
f(x: i32) { }
struct P { name: string }
union Event { timeout(after: Millis) }
void run() {
    Grams w = 0g
}
```

**Fix.** For a declaration, write the type first: `i32 f()`, `f(i32 x)`, `string name`, `timeout(Millis after)`. A missing return type becomes `void`. For a loop variable, write `for x: T in e`. For a local binding, write `let w: Grams = 0g`; the local gains `let`, or `var` when it has no value or is assigned later in its block. A `let`, `var` or `const` already written is kept: `const i32 n = 1` becomes `const n: i32 = 1`. A function type used as a field or parameter type is parenthesized so the name follows it: `(Order -> void uses net) onPaid`. The diagnostic carries the rewrite, and `bayan format` applies it.
