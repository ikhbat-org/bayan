# BYN5103: line join not indented

A lint: it never blocks a build. `bayan format` applies its fix.

**What.** A line starting with a joining token (waṣl: `.`, `?.`, `??`, `&&`, `||`, `and`, `or`, `catch`, `except`, `fails`, `uses`, `where`, `becomes`, `expects`) is indented no deeper than the line its statement starts on. Not reported: `catch` after a line ending in `}` (`} catch`), a struct-level `requires` at a field's indentation, and a line after one that already continues (ending in an operator, `,`, `=`, `=>` or an opening bracket).

**Why.** The joining token makes the line part of the statement above (spec §2.5), but at the same indentation it reads as a new statement. Indenting it deeper shows the join.

**Example.**

```
let name = "bayan"
let n = name
.length
print($"{n}")
```

**Fix.** Indent the line deeper than the line its statement starts on:

```
let name = "bayan"
let n = name
    .length
print($"{n}")
```
