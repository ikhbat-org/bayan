## B. False-Positive and Noise Traps per Phase

3. **[HIGH] H1 / `cc-wrap.sh`: `cache.byn` key poisoning and compile-vs-link flag breakage.** Because `BAYAN_CC` stays the same wrapper path while `$HARDEN_FLAGS` varies, `cache.byn`'s command/identity/flags hash can serve stale `bayan-rt.o` or binaries across sanitizer/opt modes; additionally, `cc.byn` compiles `bayan-rt.c` (`-c`) and links separately, so blindly injecting compile-only flags (or omitting `-fsanitize=*` at link time) breaks builds. Mitigation: bind a fresh `BAYAN_CACHE=$(mktemp -d)` per matrix cell, echo `$HARDEN_FLAGS` inside the wrapper when invoked with `--version`/`-v`, and inspect args for `-c` to separate compile-only flags (`-Werror=...`, `-O*`) from compile+link flags (`-fsanitize=*`). To verify how `cache.byn` probes compiler identity, I would need `src/driver/cache.byn` and `src/driver/cc.byn`.

4. **[HIGH] H3: Stripping `-w` unconditionally floods findings with harmless generated-C warnings.** Generated C triggers `-Wunused-variable`, `-Wunused-parameter`, `-Wunused-function`, `-Wunused-label`, and `-Wunreachable-code` routinely; treating every warning as an ICE per SPEC §24 will bury real bugs in noise. Mitigation: strip `-w` and enable a strict bug-class allowlist (`-Werror=implicit-function-declaration -Werror=return-type -Werror=incompatible-pointer-types -Werror=int-conversion -Werror=uninitialized -Werror=sequence-point -Werror=shift-count-overflow -Werror=strict-aliasing -Werror=format`) paired with explicit `-Wno-unused-* -Wno-unreachable-code` on generated `main.c`; compile hand-written `bayan-rt.c` separately under `-Wall -Wextra -Werror`.

5. **[HIGH] H3: `zig cc` vs `clang` false diversity, musl-vs-glibc drift, and Zig's implicit UBSan traps.** `zig cc` is Clang/LLVM under the hood, so comparing `zig cc` to system `clang` on host duplicates optimizer coverage while introducing false diffs from musl vs glibc (`printf` float formatting, `strerror`, locale) and Zig's default UBSan trapping (`SIGILL`/`SIGTRAP`) when `-fno-sanitize=undefined` is absent. Mitigation: use `gcc` vs `clang` (same host libc) as the primary differential pair; drop host `zig cc` from H3 and reserve `zig cc` for cross-targets (`wasm32-wasi`, `aarch64-linux-musl`) or pin `-target x86_64-linux-gnu -fno-sanitize=undefined` if kept.

6. **[HIGH] H4: `-fwrapv` silently disables UBSan signed-integer-overflow checks.** The toolchain always passes `-fwrapv`, which makes signed overflow defined in C and causes GCC/Clang `-fsanitize=undefined` to omit signed-overflow instrumentation; if the emitter accidentally drops `__builtin_*_overflow` on checked Bayan arithmetic, UBSan will stay silent. Mitigation: run UBSan in two passes: (1) with toolchain `-fwrapv` and `-fsanitize=undefined,bounds,float-divide-by-zero -fno-sanitize-recover=all` to catch shifts, `INT_MIN/-1`, null deref, alignment, and OOB; (2) a secondary pass with `-fwrapv` stripped via `cc-wrap.sh` on non-wrapping arithmetic tests (or cross-checked with H6) to expose raw signed C ops.

7. **[HIGH] H4: LSan fails ~100% of runs under never-freeing allocators, while ASan is blind inside custom bump arenas and fragile across `setjmp`/`longjmp`.** Five intentional leak paths exist until Q31 (`General`, `StrBuf`, `List`, caught panics, script arenas), so default Linux LSan produces total noise; conversely, sub-allocating inside a single `malloc`'d arena hides intra-arena OOB/UAF from ASan, and ASan's fake stack can false-positive across `longjmp`-based panic recovery. Mitigation: run with `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1:abort_on_error=1:detect_stack_use_after_return=0`, delete `lsan.supp` from the plan until Q31, and add an `#ifdef __SANITIZE_ADDRESS__` arena-poisoning or `malloc`-passthrough build switch in `bayan-rt.c` so ASan sees object boundaries.

8. **[MEDIUM] H4: MSan false-positive explosion against uninstrumented system libc.** H4 lists MSan as a Clang optional tier, but MSan flags false uninitialized reads across any uninstrumented glibc/libm call unless the entire C library is rebuilt with MSan. Mitigation: drop MSan from H4 until an MSan-instrumented musl sysroot exists; use Valgrind `memcheck --leak-check=no` on Linux instead (Item 16).

9. **[HIGH] H5: Fil-C traps with inline asm, `setjmp`/`longjmp`, `uintptr_t` casts, arena capability-merging, and musl-vs-glibc bootstrap diffs.** Fil-C rejects unsupported GCC inline asm, forbids forging pointers from integers, recently patched GC-root bugs in `setjmp` loops (v0.687), and merges spatial bounds if Bayan's bump arena allocates one large block via `malloc` (hiding intra-arena OOB/UAF); furthermore, `filc-0.687` uses musl, so comparing the Fil-C-built compiler's emitted C against a glibc-built compiler risks false nondeterminism from `strtod`/`qsort` differences, and 2x-5x GC overhead can trip `BAYAN_CC_TIMEOUT_S=600`. Mitigation: under `#ifdef __FILC__` in `bayan-rt.c`, route arena allocations to individual `malloc`/`free` calls so Fil-C enforces per-object capabilities; audit `bayan-rt.c` for inline asm and `uintptr_t` roundtrips first; raise `BAYAN_CC_TIMEOUT_S` for the self-host run; compare emitted C against a musl baseline if libc float/sort diffs appear.

10. **[MEDIUM] H3/H5/H8/H9: Cross-mode and cross-compiler `stderr`/signal comparison noise.** Debug mode enables `byn_own` (absent in `safe`/`fast`) and error return traces, while expected traps emit different signals across compilers/arches (`SIGILL` vs `SIGTRAP` vs `SIGABRT` vs Fil-C's trap exit). Mitigation: partition `// mode: debug` and `byn_own`-dependent goldens before cross-mode comparisons; extract Bayan's canonical trap header via regex rather than line counts; for expected-trap goldens, assert non-zero exit + matching trap message rather than exact signal number across compilers/Fil-C.

11. **[MEDIUM] H2/H6/H7: Binary-hash nondeterminism (H2), fragile `#line` regexes (H6), and wrong-code mutant rejections (H7).** Mach-O UUIDs/ad-hoc signatures on `macos-15` and ELF build-IDs/DWARF paths break raw binary diffs in H2 even when emitted C is identical; H6's `#line` invariant already disagrees with `program.byn:197-211` (`#line N "main.c"` vs none); H7 `mutate.byn` can inject parse/type errors that cause rejection for the wrong reason, hiding checker unsoundness. Mitigation: gate H2 on byte-identical emitted C everywhere and restrict binary diffs to Linux with `-Wl,--build-id=none -frandom-seed=bayan`; update SPEC §24 before implementing H6 and assert structural AST/token properties instead of line regexes; require H7 mutants to fail with the exact expected safety diagnostic code.

## C. High-Value Missed Oracles and Techniques

12. **[HIGH] Automated test-case reduction (`cvise` / `ddmin`) - WORTH IT NOW.** The handoff defers `bayan reduce` to §8 R10 and assumes manual reduction in §5, which collapses bugs/hour as soon as H4/H5/H8 find multi-hundred-line reproducers. Pick `cvise` now (full Clang passes for emitted `main.c`, `--not-c` balanced-delimiter/line passes for `.byn`) wired behind a 10-line interestingness script; what would change this is if a <150-line Bayan AST `ddmin` reducer is faster to write than installing `cvise` on wp1.

13. **[HIGH] Coverage-guided fuzzing (`AFL++` forkserver + ASan) - WORTH IT NOW.** H8's proposed black-box shell fuzzer (`fuzz.sh` spawning `bayan check`) runs ~50-200 exec/s with zero branch feedback, burning its 30-minute budget on shallow lexer paths. Because Bayan emits C11, compile the self-hosted compiler with `afl-clang-fast` + ASan (`ASAN_OPTIONS=detect_leaks=0`) and fuzz via `AFL++` forkserver (avoids Q31 OOMs that break in-process `libFuzzer` while reaching deep parser/sema/borrow-checker states at 10x-50x higher throughput); switch to `libFuzzer` once Q31 arena reset lands.

14. **[HIGH] Equivalence Modulo Inputs (EMI) on `run/` - WORTH IT NOW (pick over `smith.byn`).** `reconcile.md` confirms `--coverage` is already built for `test` and `build`, giving free execution profiles over all 378 `run/` cases. Mutating unexecuted branches (deleting dead blocks or injecting valid Bayan borrows/switches/loops inside dead regions) and checking output invariance across `debug`/`safe`/`fast` and GCC/Clang exercises real generics, error sets, and borrows at ~1/10th the cost of writing `smith.byn`; defer `smith.byn` until EMI stops yielding bugs.

15. **[HIGH] Strict-aliasing, char-signedness, and 32-bit target (`wasm32-wasi`) differentials - WORTH IT NOW.** UBSan does not instrument strict-aliasing (effective type) violations or `sizeof(void*) == 4` truncation assumptions in emitted C. Add `-O3 -fstrict-aliasing` vs `-O0 -fno-strict-aliasing` and `-fsigned-char` vs `-funsigned-char` to H3 (minutes of work), and promote `wasm32-wasi` under Wasmtime (already in `cc.byn`'s target table) to catch 32-bit pointer/size bugs.

16. **[MEDIUM] Valgrind `memcheck` + Clang Static Analyzer on `bayan-rt.c` - WORTH IT NOW.** Every bug in `bayan-rt.c` compromises both user binaries and the self-hosted compiler, yet H4 focuses on `run/` and proposes brittle MSan. Run `runtime/tests/run.sh` under `valgrind --leak-check=no --track-origins=yes --error-exitcode=1` (catches uninitialized reads without rebuilding glibc) and `clang --analyze` (<1 h to wire); revisit MSan only if CI builds an MSan musl sysroot.

17. **[MEDIUM] Csmith / YARPGen-style random generation (`smith.byn`) - NOT WORTH IT NOW.** Writing a UB-free, well-typed Bayan generator from scratch is multi-week work, and YARPGen's core strength (value-tracked expressions avoiding trivial safe-math wrappers) pays off primarily against optimizers/range analysis, which Bayan has not built yet. Defer until EMI saturates or range-analysis check elision lands; if built earlier, strictly cap scope to ~300 lines with deterministic loop bounds and safe arithmetic.

18. **[MEDIUM] CompCert (`ccomp -interp`) / Cerberus C11 reference interpreter - NOT WORTH IT NOW.** CompCert/Cerberus catch subtle C11 provenance and unsequenced-evaluation UB that UBSan misses, but Bayan's emitter relies on GNU extensions (`__builtin_*_overflow`, `-fwrapv`) that CompCert rejects. Pick Fil-C + GCC `-fstrict-aliasing` now; revisit CompCert/Cerberus only if Bayan adds a pure-ISO-C11 lowering mode without builtins.

19. **[LOW] Translation validation (`Alive2` on LLVM IR) - NOT WORTH IT NOW.** Bayan lowers straight to C11 without its own IR optimizer or range-analysis check elision, so `Alive2` validates LLVM's passes rather than Bayan's lowering (overlapping with UBSan + H3 `-O0`/`-O3` at much higher setup cost). Revisit only when Bayan builds a DIR optimizer or check-elision pass (where Z3/Alive-style proof of elision soundness is high value).

## E. Audit (`reconcile.md`) Errors and Gaps

21. **[HIGH] Audit §6 contradicts its own §2 finding by adding `tests/hardening/lsan.supp` in step 3 while turning LSan off until Q31.** Section 2 establishes five systemic intentional leak paths and concludes LSan will fire on every program until Q31, making an unused suppression file dead weight that will be stale by the time Q31 lands. Drop `lsan.supp`.

22. **[HIGH] Audit §2 and §6 understate `cc-wrap.sh` fragility as a "small" replacement for H1.** Beyond the unverified `cache.byn` identity probe the audit flags, wrapping `BAYAN_CC` must preserve compiler-vendor detection (`--version`), separate `-c` compile flags from link flags for `bayan-rt.o` + `main.c`, and cleanly strip `-w` without breaking flags containing `-w` substrings. Need `src/driver/cc.byn` and `src/driver/cache.byn` to confirm exact invocation shapes.

23. **[HIGH] Audit §6's H3 matrix (`3 cc x 3 O x 3 modes = 27x`, running `clang` and `zig` on macOS) wastes CI time on duplicate LLVM coverage.** Running both `clang` and `zig cc` on macOS tests the same LLVM backend twice, and sweeping all three `-O` levels across `debug`, `safe`, and `fast` before range-analysis elision exists multiplies runtime 2.5x-3x for minimal marginal bug yield.

24. **[MEDIUM] Audit §3 H4 assumes `CC=` in `bootstrap-build.sh:4` instruments the current compiler under ASan, which may only instrument stage 0 (`bootstrap/bayan.c`).** If `bootstrap-build.sh` compiles `bootstrap/bayan.c` with `$CC` to produce stage 0, and stage 0 then compiles `src/` using `BAYAN_CC` (not `$CC`), stage 1 will be built uninstrumented; moreover, running an ASan-instrumented stage 0 without `ASAN_OPTIONS=detect_leaks=0` will immediately fail on Q31 leaks before producing stage 1. Need `scripts/bootstrap-build.sh` to verify whether `$CC` propagates to `BAYAN_CC`.

25. **[MEDIUM] Audit §3 H10 conflates `emit/run-c.sha256` with inspectable C snapshots.** A SHA-256 digest list detects *that* emitted C changed, not *how* it changed; whether `tests/cases/emit-c/` (23 classes) already stores readable `.c` snapshots rather than hashes is unstated in the audit. Need a listing/sample of `tests/cases/emit-c/` before declaring `c-snapshots/` redundant.

26. **[MEDIUM] Audit §1/§3 H2 leaves fixpoint stage semantics ambiguous, and §6 overstates Fil-C as "Linux x86_64 only".** Section 1 says fixpoint is built "as stage 1 vs stage 2" while also quoting the roadmap that "stages 1, 2 and 3 emit identical C" without verifying whether `fixpoint-check.sh` compares stage-0 output against stage-1 output (freshness) or stage-1 output against stage-2 output (true fixpoint); need `scripts/ci/fixpoint-check.sh`. Separately, §6 labels H5 "Linux x86_64 only" despite official `filc-0.687-linux-aarch64.tar.xz` binaries existing (Item 20), though GitHub ARM64 runner availability for this repo remains unverified.
