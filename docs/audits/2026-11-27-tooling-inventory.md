## T0 core

- **Shipped driver.** The self-hosted driver is the only CLI. `AGENTS.md:6` says C# was removed in 019b and archived as tag `csharp-final`. The entry point is `src/driver/main.byn:86` `run()`. It takes global options (`takeGlobalOptions`, `--ascii`/`--color`, main.byn:181-227), then dispatches with `switch command` at main.byn:103-163. A `*.byn` argument falls through to script run (main.byn:153-161).
- **Flag parsing.** There is no shared flag library. Each command walks its own `args` by hand.
  - check, build, run and types share `t5ParseBuildOptions` (`src/driver/build.byn:44-110`). `--mode` accepts only debug, safe and fast (build.byn:67-73). `--diagnostics json|text` is at build.byn:75.
  - test has its own parser (`src/driver/test.byn:41-87`).
- **Rebuild cost.** There is no incremental compilation. The only cache is a whole-program, input-hash build cache (`src/driver/cache.byn`, spec 017 T3).
  - The one measurement is `bench/results/32330daf-baseline.txt`, dated 2026-11-05 (before 019): clean self-host build 32.6 s, one-file rebuild 30.3 s. The README says outright that there is no incremental gain (`bench/README.md`, Notes).
  - The SPEC §21.3 target of under 100 ms (`docs/bayan-spec.md:2639`) is unmet. I did not time a single `run/` golden.
- **Allocator and debug path.** See (c).
- **JSON output.** See (d). Both flags are built.
- **List layout.** `List<T>` is built. In emitted C it is a struct `{ptr, len, cap, alloc}`: initializer `{NULL, 0, 0, byn_context}` at `src/emitter/cprint/builtin.byn:167`, field decl `int64_t cap` at `cprint/types.byn:105`. It grows through `byn_list_reserve` (`runtime/bayan-rt.h:367`). There is no SoA layout.
- **Lints.** See (e).
- **Phase timing.** None. There is no `--timings` in src/, docs/specs, the roadmap or todo. `check` prints only the total elapsed time (`src/driver/commands.byn:187,215`). The lexer has a `--time` used by bench (`bench/README.md`).

## (c) Runtime allocator, debug guard, `#line`

- **General allocator.** `byn_general_resize` is a bare `realloc` that panics on OOM (`runtime/bayan-rt.c:1409-1415`).
  - `byn_general`/`byn_context` are at rt.c:1417-1418. `byn_release` frees only General blocks (rt.c:1420-1422).
  - The header says "malloc/realloc; never freed in v0.1" (`bayan-rt.h:298`).
- **Debug guard.** `BYN_DEBUG` is defined unless `BYN_NDEBUG` is (rt.c:8-13). The toolchain passes `-O0 -g -DBYN_DEBUG` for debug and `-O2 -DBYN_NDEBUG` otherwise (`src/driver/cc.byn:164-170`).
- **Reusable hook.** The existing debug-only path is the ownership checker `byn_own_*` under `#ifdef BYN_DEBUG` (rt.c:154-260+). It has no allocation hook, so T3 must add a branch.
- **Second copy of the runtime.** `src/driver/runtime.byn` is a generated copy (General at runtime.byn:2053-2061). It is regenerated by `scripts/selfhost/gen-driver-files.sh`. Its header still names the removed C# test "SelfhostDriverRuntimeTests" (runtime.byn:1). A runtime edit therefore touches two files, possibly three with `bootstrap/bayan.c`.
- **T3 call-site caveat.** User allocations reach `resize` through runtime and emitted helpers such as `byn_list_reserve` and the append helpers (`builtin.byn:212`). `__builtin_return_address(0)` will name the helper, not the `.byn` line. Emitted helpers carry `#line N "main.c"`, so they resolve to main.c.
- **`#line` emission.** Each statement gets `#line N "file.byn"`.
  - Spec: helpers carry none (`docs/bayan-spec.md:2760`).
  - Emitter: `t6ResolveResets` rewrites `#line generated` to `#line {n+2} "main.c"` (`src/emitter/cprint/program.byn:197-211`).
  - Plan 020 lists the disagreement at `docs/plans/2026-11-27-020-hardening.md:23` and gates its step 9 on it at plan:61. It is undecided.

## (f) Process, stat and stdin primitives available to Bayān code

- **Process.** Only blocking `Io.run` / `Io.runBatch` exist (`bayan-rt.h:488-516`).
  - With a timeout, `Io.run` puts the child in its own process group and sends SIGTERM then SIGKILL (rt.h:495-509).
  - There is no non-blocking spawn, no kill-by-handle and no signal or Ctrl-C handler. `Io.start` and `ChildReader` are only planned in 027 (`docs/specs/027-concurrency/027-plan.md:83,131`).
  - Consequence: a `--watch` written in Bayān cannot keep a program running while it polls. It needs 027 or a runtime addition.
- **mtime.** `Fs.modified` exists (`bayan-rt.h:629`, `src/semantics/builtins.byn:549-553`, used at cache.byn:297,812). `Fs.setModified` is at rt.h:635.
- **Sleep.** I found no sleep builtin (only the reserved name at `naming.byn:50`).
- **stdin.** `Io.stdin.readAllBytes` and `Io.stdin.read(to:)` exist (`byn_io_read_stdin_some`, rt.h:462-466). `readLine(max:)` is only planned (027-plan:83,96,288). An MCP server would have to frame lines itself on top of `read(to:)` until 027 lands.
