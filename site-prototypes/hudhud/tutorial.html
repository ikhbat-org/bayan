Your first program

Five steps from nothing to a native executable, including the one where the compiler tells you something is wrong.

  1. Get the compiler

    Bayan builds from source today. You need the .NET 10 SDK, and zig on your PATH for the native step.

    terminal
    $ git clone https://github.com/ikhbat-org/bayan
$ cd bayan
$ dotnet publish src/Bayan.Cli -c Release -r osx-arm64 -o tmp/publish
$ ./tmp/publish/bayan --version

    Use the runtime identifier for your system in place of osx-arm64. Put the bayan binary on your PATH, then run bayan doctor: it checks the C compiler, zig, git and the build cache, and says how to fix what is missing.

  2. Write hello

    Create hello.byn. Newlines end statements; there are no semicolons.

    hello.byn
    let name = "Bayan"
print($"Hello, {name}!")

  3. Build it

    Bayan emits C and hands it to zig cc. The result is a plain executable.

    terminal
    $ bayan build hello.byn -o hello
◆ built hello (safe, macos-arm64) in 0.68s

  4. Run it

    terminal
    $ ./hello
Hello, Bayan!

    bayan run hello.byn does both steps at once. To start a whole project instead, use bayan new hello.

  5. Read an error, fix it

    Mistype the name in the second line: {nme} instead of {name}.

    terminal
    $ bayan run hello.byn
error BYN2001: `nme` is not defined
  --> hello.byn:2:17

  2 │ print($"Hello, {nme}!")
    │                 ^^^
    │
    │ help: did you mean `name`?
    │ 2 │ print($"Hello, {name}!")

✗ build failed: 1 error, 0 warnings
  explain: bayan explain BYN2001

    Read it top to bottom. What: nme is not defined. Where: line 2, column 17, under the three carets. How: the help line suggests name and shows the corrected line. Make that change and run again.

    terminal
    $ bayan run hello.byn
Hello, Bayan!

    Next: argument particles, or bayan --help for every command.
